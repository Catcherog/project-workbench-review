# UI 原型与审核路线

本包保存独立的 Apple 风格工作台原型，供三方协作中的 UI 讨论与审核。保留「项目、风险、数据、周例会、助手」五个入口；玻璃效果用于导航和操作层，业务内容采用稳定底色。

## 打开与源码

下载固定提交中的本目录后，直接用浏览器打开 `preview/light.html` 或 `preview/index.html`。GitHub 文件页展示源码，不会自动运行交互；本次没有配置 GitHub Pages 或其他网站托管。

`source/workbench-apple-glass.html` 是原可编辑片段，包含样式和完整交互逻辑，依赖原预览宿主的图标与状态接口；独立浏览器体验应打开已带导出包装的 `preview/*.html`。这些页面继承原导出包装，图标及辅助库使用固定版本公开 CDN，因此不保证完全离线可用。全部业务保存和消息发送只在前端模拟，页面没有业务后端地址。

`preview/light.html` 对应来源窗口最后显示的浅色版本；`index.html` 跟随系统外观。其余三份分别预设混合发送、保存失败、保存结果未知，用于直接体验异常分支。保留原包各版本默认值，没有新增或更换技术框架。

## 已确认交互

1. 先看需要谁做什么和关键时间，再展开摘要、依据和历史。
2. 在原事项里一次输入进展与手动时间。普通记录成功后回原列表；混合讨论留场；失败或结果未知保留输入。
3. 消息按项目与节点集中预览，完整展示每条收件人、正文和随附资料，可编辑、取消或部分批准。
4. 发送成功、明确未发出、结果待核实分别呈现；未知结果先核对，人工接手与交回分别操作。
5. 保存、更改安排、外发消息和纳入跟进分别留状态。撤销遇到后续修改冲突时阻止整次撤销。

这些是原型表现目标，不代表对应产品能力已经集成或验收。

## 建议检查路线

| 页面 | 操作与可观察结果 |
| --- | --- |
| `light.html` | 风险 → 关键回归测试事项 → 输入普通进展 → 提交，出现保存回执并回列表；撤销后还原原安排 |
| `light.html` | 助手 → 消息预览 → 完整预览，三条消息全文及收件人可见；取消一条后只模拟发送保留消息 |
| `mixed.html` | 同样打开消息批次，确认后分别显示成功、明确未发出及待核实；先核实未知，人工接手后不自动重试 |
| `save-failure.html` | 风险 → 任一事项 → 输入 → 提交，保留输入并明确未写入 |
| `save-unknown.html` | 同上，保留草稿并显示结果未知，不假报成功 |
| 窄窗口 | 打开长消息预览后缩窄窗口，检查正文自动展开、标题及操作可找到；用 Escape 返回事项列表 |

本轮新增检查的确切范围见 `evidence/publication-checks.json`，其余路线引用历史记录或留给审核方操作，不代表本轮重复执行。

## 体验评价与限制

原作者的实际体验结论：简洁清单与原事项面板便于接续；整批全文预览能看清批准范围；正文稳定底色比全页透明更适合阅读。正式接入后还需用大批量消息、真实等待时间和完整业务流程检查信息负担。

本轮脱敏只替换显示称呼与头像，并去除报告中的本机路径；所有原 HTML 的业务分支和样式保持。原截图不公开，`screenshots/` 为公开副本重新截取的画面。

具体限制：

- 日期基于 10 月 13 日的固定示例。文本理解是简化匹配；本轮输入含“明天下午”的句子时，回执给出 10 月 14 日 10:00，不能据此声称自然语言时间理解正确。审核交互请优先使用明确的手动时间控件；正式接线需要真实时间理解及其测试。
- 图片、真实模型、权限和附件读取未接入，示例随附资料不等于可读取真实文件。
- 状态由独立导出包装保存在浏览器演示环境，不能等同于正式数据库保存、审计日志或真实业务恢复。
- 这次不解决原对话的系统报错，也不重新开发整个 UI；已接管的是其未完成的审核回传。分享链接与本机聊天 ID 的映射未独立验证，匹配依据见当前交接。
- 上传、固定提交读回、GPT 独立审计、用户验收和正式产品交付分别记录。
