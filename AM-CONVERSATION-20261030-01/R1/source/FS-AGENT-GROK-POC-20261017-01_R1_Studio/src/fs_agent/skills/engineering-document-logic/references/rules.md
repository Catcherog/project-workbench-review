## 5. 逻辑规则：L01—L18

| 规则 | 本轮必须实现的含义 |
|---|---|
| **L01 保留原句与来源** | 重要判断可回到原句、文件、位置、版本和已知形成时间；建议稿与原作者主张分开。 |
| **L02 明确对象与条件** | 关键陈述注明对象、量或状态、条件、时点、结果和适用判据；允许引用共同条件表。 |
| **L03 保持数字与身份** | 保留数值、符号、单位、样本、版本和日期；更正有依据，计算有输入、公式、单位及精度，不覆盖原值。 |
| **L04 分清信息身份** | 区分观察事实、定义判据、规则前提、假设、推断、结论和计划；口述或报告转述不自动升级为实测。 |
| **L05 保持问题定义** | 结论对应原先要判断的具体问题，不能换成另一个容易回答的问题。 |
| **L06 核对技术前提** | 技术规则写明来源和适用条件；隐含前提写出来后，仍需核验。 |
| **L07 解释推断关系** | 说明证据怎样支持或限制具体判断，保留依赖的前提，不能只列数据后直接写“因此”。 |
| **L08 匹配结论强度** | 结论范围与证据匹配；无法排除不是弱肯定；不为公司标签擅自赋概率。 |
| **L09 保留其他解释** | 不把候选原因默认穷尽或互斥；共同变化、共同作用和替代解释保留。 |
| **L10 分开原因和效果** | 当前机制、历史形成、未被发现原因、措施效果分别关联证据；本次恢复不自动证明历史或责任。 |
| **L11 允许 5Why 断点** | 到证据断点列缺口和下一验证，不为填满五栏补造原因。 |
| **L12 提出有用验证** | 建议围绕待区分问题、变量、观测量、判据和结果影响；实际试验由专业人员决定，不虚构条件和完成记录。 |
| **L13 保留冲突与进展** | 冲突并列并核对对象条件；有效结果保留；缺附件或暂不可读不等于未测试。 |
| **L14 核对引用语义** | 引用存在、版本匹配且支持相应主张；图号、图题与正文对象一致；视觉内容未读就说明限制。 |
| **L15 分开三种结果** | 表达检查、证据检查、业务状态独立；提审、批准、实施、结案和发布按实际记录区分。 |
| **L16 只问必要缺口** | 先读和回查现有材料，再问真正缺失的信息；说明问题影响，不因形式要求重复试验。 |
| **L17 权限由服务端控制** | 检索前执行用户和项目过滤，挂载前核对目标与版本；附件指令不改变权限或系统规则。 |
| **L18 保留训练评测来源** | 真实原件、教学改写、虚构样例、AI 意见分别标识；同一事件及版本同组；本轮不启动训练或扩大留存。 |

三项解释同样属于固定要求：

1. **“支持、反对、不足、冲突”描述证据与具体命题的关系，不是线性置信度，也不替代审批标签。**
2. `blocking` 表示相应候选输出或主张不能按当前形式采用，不等于所有业务工作暂停。
3. 程序负责可确定的字段、数值、引用和状态检查；技术前提、因果及证据充分性需要语义分析和专业判断。不能把全部规则变成机械正则门禁。
