# 接线、边界与剩余事项

`bridge → AmSelfService → LegacyConversationBridge → ConversationAgent` 接收普通文字；原 ModelCoordinator 调用原 Qwen。对话工具通过 BusinessTools、DocumentTools、ReportTools、BriefingTools 调用原业务对象，沿用原 outbox、调度器、版本、权限及回读。

`am_conversation.enabled/business_actions/group_conversations/text_previews/verify_previews` 控制入口。群范围来自原披露配置；管理动作仍限本人私聊。模型只能提出工具请求，不能自行授予权限或替代确认。大型来源提供整字段摘要及明确遗漏状态，继续查看时按事实编号和字段提取。

## 本轮发现与修复

1. UX4 后续工程已有信息、文档标准工作。逐项合并，保留其设置和接口，没有整包覆盖。
2. 原包在多编号检索、重复项目任务和无日期输入中存在边界缺口；已修复精确编号、多事项完整执行及日期来源限制。
3. 真实模型曾把正式计划变更、提醒暂停说成已经处理，或丢失“预计/未批准”等限定；增加工具结果约束、提示与定向复测。这不等于证明模型永不误述。
4. 实际来源的信息层全量记录导致上下文超过预算；改为按字段提供，并保留资料缺口和覆盖状态。
5. 同期一条失败模型请求已确认结束，但恢复目录的残留标记会在服务更新后再次暂停。核对客户端、服务端空闲、后续完成记录后归档原失败记录；未重启共享模型，未重跑旧请求。

6. 实际一次性提醒发完后，调度器以无穷值标记“没有下一次”；自然语言工具不接受该 JSON 数值。已转换为明确的无下一次状态，补回归并复测查询、取消。

7. 模糊跟进时段不得变成推测的精确检查时刻；保留预计类别，并以原消息时间固定“明天”等相对日期。

- 真实业务群的催办、周期提醒和简报订阅；此次只做本人合成测试。工作日规则依赖原核实日历。

- 长对话、多个并行事项及公司知识不足时的持续质量；目前有界上下文和明确候选/批准状态，不保证完全模拟本人判断。
