# 聊天读取与 GitHub 审核通道

首次接入、材料读取失败、目标 / 权限 / 连接变化或回传故障时按对应部分使用；正常轮次核对本轮对象与版本即可。决定与授权沿用主文件，不重新询问已明确的可见性和范围。

## 指定聊天与必要附件

1. 使用当前可用且获授权的聊天读取能力，核对实际聊天链接 / ID、任务 / 轮次和交接消息。只有标题时先定位唯一对象；无法消除歧义只询问该定位项，不拼造聊天 ID、CLI 或下载地址。
2. 读本轮交接及判断确认 / 覆盖关系所需的消息，记录截止位置。只读取明确引用的相关窗口；工具只给摘要、截断文本或分页时补读必要原文，未取全则说明范围，不能标成完整读取。
3. 列出本轮必读附件及必要依赖，通过实际附件引用下载并读取。聊天、`sandbox:`、Library、Page 和本机文件的定位方式不同，不把远端路径直接当本机文件。记录来源、文件名、版本；已下载文件可用校验值固定快照。同名本地文件不代替下载证据。
4. 简单文字交接没有附件就直接执行；不枚举下载所有历史文件。实际失败时区分无工具、引用失效 / 缺失、权限拒绝、网络错误与目标不存在，只暂停依赖材料的工作，独立检查继续，必要时只补缺失项。

能力记录应区分“聊天正文已读、附件已下载、附件内容已读”。本轮读通不保证其他账号、聊天或执行环境可读；读取成功也不授权发消息或自动唤醒。输入快照固定本轮依据，但晚到的暂停、撤回或收窄授权立即约束相应动作；新增要求另作明确变更交接。

## 选择目标

先检查当前项目真实远端、交接入口和用户选定通道。分别处理聊天交接与审核回传，两者不必使用同一种存储。复用已确认仓库，在本任务独立路径保留历史轮次，不覆盖其他任务或已验收阶段的入口；只有既有约定允许才改全局索引，不为每轮新建仓库或把项目仓库写死进通用 Skill。

| 场景 | 处理 |
| --- | --- |
| 已有远端 | 核对身份、可见性、读写能力与发布范围，多远端时确定本轮目标 |
| 需要完整项目版本管理 | 使用已获相应文件和历史上传授权的项目远端 |
| 只需交换审核材料 | 在独立工作目录维护审核仓库和独立 Git 历史，保留来源清单 |
| 暂无可用通道 | 执行方准备一次必要的精简回传；已授权本地实现和验证继续 |

用户未指定可见性时，先准备私有方案；已明确选择公开时采用下节方案。列明账号、候选仓库名、拟上传内容及范围，核实命名冲突；只有真实缺口才补充决定。不要让用户手工找路径、整理源码或制作压缩包，也不要用无关仓库接收本项目材料。

账户有写权限、执行方能 push、同一账号登录均不证明审核方能读取某个私有对象。按当前环境的真实工具与授权验证。

## 公开审核材料

- 使用独立目录与历史生成审核副本，不把原项目根目录或完整历史整体推送。首次可只发布不含业务内容的通道测试文件。
- 只包含本轮必要的去标识化需求、差异或选定源码、合成数据下的验证结果。检查拟提交内容，排除凭证、令牌、真实业务数据、内部文档原件、个人信息、私人聊天、无关附件、敏感截图 / 日志和无关历史；不破坏性改写原项目来制作副本。
- 对去标识化的路径和数据保留内部映射，说明审核副本与受测源码的关系；保留影响判断的条件、控制流和验证事实，不把简化实现冒充受测原始代码。
- 原始证据不适合公开时，定向补充必要私下材料或说明审核限制。只有确需新增公开信息或超出既有范围时，暂停相应上传，可独立工作继续。

## 用最小对象验证

1. 在授权覆盖的目标建立仓库或使用指定独立测试位置，上传无业务内容的测试文件，包含随机校验值与时间。
2. 接收端读取实际提交与测试正文，核对来源、校验值和内容。网页可访问、仓库列表、执行方本地读回及工具定义都不替代接收端实读。
3. 成功后记录固定入口、对象范围、读写动作、时间和证据；在既有授权内发布本轮必要材料。项目源码提交与审核导出提交分别记录。
4. 失败时区分无工具、对象引用缺失、未配置、权限拒绝、网络错误与目标不存在；权限拒绝须有对应授权或配置变化才重试，网络故障按新证据定向重试，不盲目循环，不换隐蔽凭证或无关通道绕过。

私有读取无法解决时，按用户选定后续方式推进，不自行改为公开或新增接收方；没有公开授权就保持私有，使用精简回传或其他已验证通道。单次私有读取失败不推导为所有产品都不能读取私有仓库。

## 保持可审核

回传纳入本轮相关修改、新文件、删除、重命名及必要未提交内容，避免遗漏普通 diff 未覆盖的文件。不默认回传整个仓库、所有旧附件、生产数据或完整历史。

使用任务内 `00_当前交接.md` 汇总必要状态，小任务不强制拆多份报告。涉及源码变化时提供本轮 diff、相关最终文件和理解改动的最小上下文，或 GPT 可读的源仓库固定版本。未跟踪文件不能只靠普通 diff；清单应说明增改删、重命名及未提交内容如何纳入。源项目的基准、实现提交 / 工作树状态与审核仓库提交分开，旧 HEAD 不代表未提交的受测内容。

上传后从远端固定提交读取入口和必要文件，核对存在性、正文或校验值，再回传固定提交链接。浮动分支不足以固定证据；提交成功后在回传消息中给 SHA 即可，不为让文件包含自身 SHA 循环提交。上传成功、Codex 远端读回、GPT 独立读取与审计分别记录；读回失败不能写成未上传，也不能宣称接收端已读到。

图片、样例与日志有接收方可读位置，出现图片链接不等于审核方已看到图片。必要私有证据不能公开时说明缺口及其限制，不用简化材料冒充完整原件。审核回传不授予业务源码 push、merge、正式部署或真实业务外发权限。

## Skill 持久化与加载核对

需要更新 Skill 时先核对原身份及真实正式源，再用已验证的保存方式原位更新；工作副本只用于准备和验证。保存后分别读回主文、相关引用和必要元数据，记录身份、实际版本 / 校验值与来源。持久化成功、云端界面可读、执行端文件可读和自动加载各列状态；未挂载、引用不可读或无加载证据时如实报告，不另装同名副本或改插件权限来伪造生效。
