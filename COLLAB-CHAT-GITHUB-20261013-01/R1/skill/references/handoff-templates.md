# 聊天交接、回传与审计模板

按本轮情况合并或删去无关字段；不要生成多份重复入口。所有占位符应在交付前填成已知内容，未知项明确标注并限定其影响。

## 小修复

一段话包含：实际来源聊天 / 交接定位、任务 / 轮次与有效依据；要改的行为和本轮边界；可观察的完成判据、授权停止点与回传位置。无附件时写“无，按聊天交接执行”，不要求先生成文件。继承已确认决定，不为小修复重新走通道配置或用户交互选择。只有确有必要时补充下列完整结构。

## GPT → Codex 启动提示词

聊天中已写清要求时，只转这段即可；精确定位能够取得就直接填入，取得不了只补该项，不留下看似真实的假链接。

```text
执行 [任务 / 轮次]。读取 [实际聊天链接 / ID] 中 [交接消息标识、截止位置或唯一可辨识定位] 的“本轮执行交接”，下载并完整读取 [必读附件及版本；无则写无]，参考附件按需要读。
记录实际采用的要求、来源范围和覆盖关系；未确认讨论不作任务。继承有效基线及已有授权，做到 [本轮验收标准与停止点]。
按已确认 GitHub 渠道，在 [任务内独立路径] 回传必要差异、相关文件与验证，远端固定提交读回后给审核入口。不要求用户重抄聊天、整理附件或重打包；缺材料只补该项，可独立工作继续。
```

## GPT → Codex 本轮执行交接

```text
本轮任务：[编号 / 轮次与标题]
角色：你是执行方，负责项目文件、实现、验证和回传；重要用户决定以本任务及其有效基线为准。

一、接续依据
来源：[实际聊天 / 交接消息定位和截止位置]
项目：[真实项目、路径或远端]
当前交接入口：[路径]
有效需求：[基线路径与版本、适用条目]
代码依据：[已审核提交/当前工作树的已知状态；执行前核对实际情况]
替代关系：[补充/替代哪些任务或条目，其他已确认规则继续有效]

二、目标与范围
结果：[本轮应达到的状态]
范围：[涉及功能与文件边界]
授权：[已授权动作、范围和来源；停止点及确实未授权的后续动作]

三、本轮要求
[逐项列出新增/修改规则、继承行为和必要条件]
必读文件：[实际附件引用 / 文件名、版本及用途；无则写无]
参考文件：[仅列相关项；不要求全读历史附件]
[未决问题及其影响；明确可独立继续的部分]

四、完成标准
[场景 → 操作 → 预期可观察结果；覆盖相关失败或恢复路径]
[所需验证与证据；已有有效证据可以复用]

五、记录与回传
先在现有任务记录保存本轮指令和输入快照（聊天、消息截止、采用要求、覆盖关系、附件及读取缺口），再维护有效基线；只读任务在回复中记录，不修改文件。区分原始任务、执行事实和待确认事项，不增加平行权威副本。
在授权范围内执行，不要求用户重新确认已经确定的普通细节；真实冲突仅暂停受影响部分。
提供本轮完成/未完成项、实际相关差异或必要源码、验证证据及运行状态。纳入本轮相关的新文件，不将无关工作一并提交。
回传位置：[已确认通道和任务独立路径；不可用时采用何种最小替代]
上传前检查敏感内容；上传后从远端固定提交读回入口与必要文件，不覆盖别的任务 / 阶段。
版本定位：[源项目代码依据；有审核仓库时另给其分支、提交和入口]
未验证项与下一步：[按事实填写]
```

实际完成：
未完成/偏离及原因：
原始任务记录位置：

受测代码 / Skill 依据：基准、实现版本 / 分支或内容校验值；无则说明
本轮修改/新增/删除：
相关差异或源码位置：
未提交与未跟踪的相关内容如何纳入：

验证：场景或命令 / 结果 / 对应代码依据 / 证据位置
状态：源码 / 构建 / 静态或模拟验证 / 安装 / 真实运行与集成 / 发布 / 用户验收
涉及 Skill 时：正式身份与保存方式 / 持久化主文及引用读回 / 实际加载来源读回；不可验证端单列
未验证项：

回传通道：
审核仓库完整提交与固定入口：
上传结果 / Codex 远端读回：
GPT 独立读取与审计：待执行（有真实证据才改状态）

不要求每次填写长表。用最少的字段准确定位本轮要求、代码和证据；没有执行的动作直接写“未执行”。

## GPT 审计后 → Codex 修复 / 补证

先实际读取固定提交入口和本轮关键材料，再填写；只有摘要时不能通过，也不凭缺证据断言实现有缺陷。满足验收标准即可结束本轮，不为填模板制造下一轮。

```text
审计对象：[任务 / 轮次、审核仓库完整 SHA、实际读到的入口与文件]
结论：[通过 / 需要修复 / 证据不足 / 需要用户决定；注明实际覆盖范围]
阻塞问题：[具体事实、影响、文件或证据定位；无则写无]
非阻塞建议：[单列，不自动成为返工]
运行 / 发布 / 用户验收状态：[分别说明，不从审计通过推导]

仅在确需修复或补证时继续：
下一轮：[复用任务编号并递增轮次，关联上轮固定提交]
本轮执行交接：[只写必要修复或最小缺证材料、完成判据、继承授权与停止点]
必要文件：[实际引用；无则不生成文件]
回传：[复用任务独立路径和固定提交规则]
执行前提：用户实际启动本轮且授权仍有效；不自动触发下一阶段。
```

## 现有入口中的协作状态

```text
协作分工：规划审核方 / 人工复审方 / 执行方
当前阶段、任务与有效基线：
任务传递：发送端 → 接收端 / 方式
审核回传：发送端 → 接收端 / 目标与入口
通道状态：实测可用 / 未验证 / 未配置 / 当前不可用
实测依据：对象、读写动作、结果、时间；本方实测或接收端报告
当前授权：动作、范围、来源；发布与合并分别记录
当前待处理：负责人、具体缺口、可独立推进的工作
```

把通道状态与产品实施状态分开。接收端未读通云端文件不等于产品实施被取消；有代码提交也不等于已安装或已验收。
