## 2. 目标、范围与授权停止点

### 2.1 目标

工程师通过既有飞书入口发送文字、文件或补充信息后，系统能够：

1. 读取资料，明确对象、版本和阶段。
2. 提取事实、判据、假设、推断及结论。
3. 建立重要判断与证据的对应。
4. 回查已有资料，只追问影响当前判断的必要缺口。
5. 生成可读候选稿或准确阶段稿。
6. 提供关键修改、来源索引及未解决项。
7. 分别给出表达检查、证据检查和实际业务状态。
8. 沿用有效提交意图或确认流程，向正确项目、节点、交付物及版本保存／挂载。
9. 对失败、重试、更新和撤销给出准确、可恢复的结果。

**完整流程要求当前已知、未知、结果和业务动作得到准确处理；不要求每份文件的技术根因都已确认。**

### 2.2 执行范围

Codex 在现有源工程和隔离工作区完成：

- 本轮实现和必要模块接线。
- 范围内普通修复。
- 定向验证。
- 候选安装／发布准备。
- 脱敏审核回传。

已有授权覆盖的试用安装和真实集成直接继续，不重复索取相同授权。

正式服务变更、源码 push／merge、新权限、新测试对象、真实业务外发和模型训练，分别核对已有有效授权。确实超出授权时，先把准确差异、影响和验证结果准备好，再集中说明缺口；其他可独立工作继续。

不得破坏性重置工作树、覆盖人工修改、强推、切回旧运行源码、启动未经核实的第二消费者，或为测试放宽既有身份和隔离规则。

## 4. 完整业务流程：P01—P12

| 步骤 | 触发与操作 | 固定行为与结果 |
|---|---|---|
| **P01 接收** | 工程师发送文字、文件或补充信息 | 继承成员／部门范围、私聊和群聊仅 @ 规则；及时反馈已收到，随后异步处理。原约 3 秒要求用于接收反馈，不等于全部整理完成。 |
| **P02 定位** | 识别用户、任务、项目、节点、交付物类型和阶段 | 能从授权信息唯一确定就直接使用；同名、归属不清或缺少必要目标时，仅补齐相应歧义。未选择挂载目标不阻止先整理已获授权资料。 |
| **P03 读取** | 处理本次材料及必要关联附件 | 保留来源身份、版本和位置，记录完整／部分／失败的读取范围。首版必须走通文字及至少一种实际工程文件格式；不支持内容如实说明，不静默遗漏后声称全文检查。 |
| **P04 提取** | 抽取对象、条件、时间、数值、判据及重要句子 | 分开保存事实、规则、假设、推断、结论和计划。原值与派生值分开；未知字段保留缺失原因。 |
| **P05 对应** | 为重要判断建立证据索引 | 记录支持、反对、不足、冲突及推断摘要；引用对应具体命题和版本，不能仅检查链接存在。 |
| **P06 回查** | 材料存在缺口或冲突 | 在当前权限和项目范围内查找已有记录；当前事实、规则和教学案例分开使用。检索命中不能代替本次提交全文的读取。 |
| **P07 补充** | 仍有影响当前阶段的重要缺口 | 合并必要问题、说明影响；接收回答并注明来源。工程师可选择补充、先形成阶段稿、暂停或放弃本次草稿。 |
| **P08 生成** | 材料足以形成有用候选稿或阶段稿 | 输出可读文件、关键修改及理由、证据索引、待确认项；保留有效进展和结论范围。 |
| **P09 检查** | 对候选稿进行程序和语义检查 | 分别给出表达、证据和业务状态；关键失真先修正或限制相应主张，不能用语言流畅抵消事实错误。 |
| **P10 采用** | 工程师选择采用、修改或补充 | 已有有效提交意图和确认不重复索取；仅处理实际变化的目标、内容或范围。专业审核继续由原角色完成。 |
| **P11 保存挂载** | 具备对应动作的有效意图与权限 | 服务端复核用户、项目、节点、交付物、内容及目标版本；正确保存／挂载，保留实际回执。新内容不自动继承仅对旧内容有效的批准。 |
| **P12 返回与接续** | 成功、失败、结果未明、更新或撤销 | 返回实际文件和准确状态；失败保留可恢复结果；写入未明先对账；晚到结果不覆盖新稿；撤销不扩大为删除历史文件或回滚项目。 |

流程中的返回关系：

- P07 补充后，可以回到 P06 查证，或者进入 P08 生成。
- P10 修改后，回到受影响的提取、生成和检查步骤。
- 没有变化的材料和已经回答的问题继续复用，不从头盘问。

首版聚焦 **8D／异常分析和测试报告**。其他文种可共用基础结构，但全部文种、通用 OCR、知识图谱和独立向量数据库不作为首轮前置条件。

## 5. 逻辑规则：L01—L18

| 规则 | 本轮必须实现的含义 |
|---|---|
| **L01 保留原句与来源** | 重要判断可回到原句、文件、位置、版本和已知形成时间；建议稿与原作者主张分开。 |
| **L02 明确对象与条件** | 关键陈述注明对象、量或状态、条件、时点、结果和适用判据；允许引用共同条件表。 |
| **L03 保持数字与身份** | 保留数值、符号、单位、样本、版本和日期；更正有依据，计算有输入、公式、单位及精度，不覆盖原值。 |
| **L04 分清信息身份** | 区分观察事实、定义判据、规则前提、假设、推断、结论和计划；口述或报告转述不自动升级为实测。 |
| **L05 保持问题定义** | 结论对应原先要判断的具体问题，不能换成另一个容易回答的问题。 |
| **L06 核对技术前提** | 技术规则写明来源和适用条件；隐含前提写出来后，仍需核验。 |
| **L07 解释推断关系** | 说明证据怎样支持或限制具体判断，保留依赖的前提，不能只列数据后直接写“因此”。 |
| **L08 匹配结论强度** | 结论范围与证据匹配；无法排除不是弱肯定；不为公司标签擅自赋概率。 |
| **L09 保留其他解释** | 不把候选原因默认穷尽或互斥；共同变化、共同作用和替代解释保留。 |
| **L10 分开原因和效果** | 当前机制、历史形成、未被发现原因、措施效果分别关联证据；本次恢复不自动证明历史或责任。 |
| **L11 允许 5Why 断点** | 到证据断点列缺口和下一验证，不为填满五栏补造原因。 |
| **L12 提出有用验证** | 建议围绕待区分问题、变量、观测量、判据和结果影响；实际试验由专业人员决定，不虚构条件和完成记录。 |
| **L13 保留冲突与进展** | 冲突并列并核对对象条件；有效结果保留；缺附件或暂不可读不等于未测试。 |
| **L14 核对引用语义** | 引用存在、版本匹配且支持相应主张；图号、图题与正文对象一致；视觉内容未读就说明限制。 |
| **L15 分开三种结果** | 表达检查、证据检查、业务状态独立；提审、批准、实施、结案和发布按实际记录区分。 |
| **L16 只问必要缺口** | 先读和回查现有材料，再问真正缺失的信息；说明问题影响，不因形式要求重复试验。 |
| **L17 权限由服务端控制** | 检索前执行用户和项目过滤，挂载前核对目标与版本；附件指令不改变权限或系统规则。 |
| **L18 保留训练评测来源** | 真实原件、教学改写、虚构样例、AI 意见分别标识；同一事件及版本同组；本轮不启动训练或扩大留存。 |

三项解释同样属于固定要求：

1. **“支持、反对、不足、冲突”描述证据与具体命题的关系，不是线性置信度，也不替代审批标签。**
2. `blocking` 表示相应候选输出或主张不能按当前形式采用，不等于所有业务工作暂停。
3. 程序负责可确定的字段、数值、引用和状态检查；技术前提、因果及证据充分性需要语义分析和专业判断。不能把全部规则变成机械正则门禁。

## 6. 追问、停止与阶段稿

至少区分以下五种状态：

| 状态 | 对应处理 |
|---|---|
| 已提供且可读 | 直接使用，不重复询问 |
| 已提供但暂不可读 | 说明具体读取限制，不写成没有该资料 |
| 已读记录缺字段 | 针对影响当前判断的缺口提问 |
| 记录相互冲突 | 并列冲突，核对对象、条件和版本 |
| 现有资料无法回答，需要工程验证 | 保留未知与建议，由专业人员决定后续验证 |

固定行为：

1. 先使用已提供信息，再回查授权范围内的资料；同类缺口合并提问。
2. 每个问题关联受影响的判断，说明为什么需要，不要求工程师手填全部内部字段。
3. 已明确重插线缆，就不再问是否重插；应查是否有能区分两项操作影响的记录。
4. 用户回答“不知道／没有记录／暂时无法提供”后，保留该状态；可以继续形成阶段稿。
5. 没有新的有效输入时，不重复追问、不自动催办、不循环生成。防循环保护可以实现，但不能用任意轮数代替业务停止条件。
6. 工程师可主动先生成阶段稿、暂停后补充或放弃本次草稿；恢复时沿用已有材料和未解决项。
7. AI 可以提出验证建议，不能编造样本量、已完成试验、负责人、截止日期或责任认定。建议值必须标注为待专业确认。
8. 需要其他数据提供者时，沿用已有获准联系流程；本任务不自动授权向同事、群或领导发送新消息。
9. 身份、权限、目标和版本缺失时，只阻止对应读取或写入；能独立进行的整理继续。

## 7. 文件内容和输出契约

### 7.1 日常五项基础结构

| 字段 | 内容 |
|---|---|
| 本次问题或决策 | 本次处理什么，或请别人判断什么 |
| 已知事实与来源 | 已观察、测量、完成或收到什么，对应哪份材料 |
| 当前判断与理由 | 证据支持什么，依据和适用前提是什么 |
| 范围、缺口与冲突 | 适用范围，还有什么未知或不一致 |
| 下一步与完成证据 | 接下来查什么／做什么，用什么证据确认完成 |

对象、版本、样本及共同条件可以集中引用，避免全文重复。负责人和日期只使用实际确定的信息。

首批文种的补充要求：

- **8D／异常分析：**在既有模板中分别处理现象、发生原因、流出原因、措施和效果验证，不增加一套平行表单。
- **测试报告：**明确判据、样本、条件和结果；区分通过、失败、未测、受阻；统计口径没有依据时保留未知。

### 7.2 每次整理必须交付

1. **可读候选稿或阶段稿。**优先使用既有工程可交付格式，不强制另建编辑器。
2. **关键差异及理由。**尤其列出结论范围变化、数值修正和重要删改。
3. **关键判断的证据索引。**能定位到文件及页、段、单元格或图号等已有位置。
4. **待确认项及影响。**已经回答或已查到的项不再重复出现。
5. **表达、证据、业务状态三项结果。**
6. **实际保存／挂载结果。**已写入时提供真实可打开对象及目标，尚未写入时不能显示已挂载。

页面优先展示工程师能理解的信息。模型参数、内部字段和检查程序名称留在诊断界面。沿用现有卡片结构，必要动作围绕查看、补充、阶段稿、采用／挂载及放弃当前草稿。

### 7.3 内部最小信息

复用现有实体和存储，按需要补充：

- 任务／事件标识、用户和项目范围、目标交付物。
- 来源和版本、原句、建议句、信息身份。
- 证据关系、结论范围及未解决项。
- 规则版本、模型配置版本。
- 实际业务状态来源。
- 用户采用记录和写入回执。

缺失值保留 `null` 及原因，不补成否、0、无、未执行或默认批准。

模型完成、文件保存、挂载、专业审核及节点完成使用可区分的记录；不要求业务系统因此新增五套状态字段。

## 8. 采用、版本、挂载和恢复

以下十条固定适用：

1. **沿用既有有效意图或确认。**确定内容、确定目标和授权条件均未变化时，不重复确认。
2. 单纯“整理一下”不扩大为对外发送、专业批准或节点完成。
3. 保存前核对内容版本、真实目标和当前修订；使用平台实际可用的修订值或内容指纹，不虚构字段。
4. 目标或内容实质变化时，只处理受影响部分；旧稿采用或批准不静默迁移给新稿。
5. 同一事件重放、模型重试和发送失败不得造成重复挂载；复用已有幂等能力，缺失则补本轮所需的最小实现。
6. 远端可能成功但应答丢失时，先对账；无法确认则显示“结果待确认”，不盲目再次写入。
7. 写入前有效撤销阻止仍可停止的动作；旧任务或旧版本的晚到结果不能覆盖新稿。
8. 远端提交后才收到撤销，说明已发生的结果和已停止的后续动作；不宣称未写入，不自动删除远端文件或回滚整个项目。
9. 模型、读取或转换失败保留已完成且可恢复的工作；重试保持已确认的目标和内容范围。
10. 交付物“已审核”和节点完成继续依赖权威记录与既有条件；候选稿检查通过不改变它们。

## 9. 技术实现分工

| 部分 | R1 工作 |
|---|---|
| **Skill／规则包** | 通用规则、文种模板、正反示例、必要追问策略和检查调用；记录版本及实际加载来源 |
| **Agent 流程** | 读取、提取、回查、补充、生成、检查、采用、写入和恢复，优先受控流程 |
| **检索** | 当前权限及项目范围内的资料和判据；当前事实、规则、教学案例分开用途 |
| **程序检查** | 字段、原值、单位、编号、引用存在性、版本和实际写入状态 |
| **Qwen** | 内容提取、改写和语义检查；按实际模型能力处理结构化输出，不能以 JSON 合法代表语义正确 |
| **专业审核** | 技术前提、证据充分性和专业采用，不被 AI 自评分取代 |
| **SFT** | 仅预留后续评价所需字段和导出接口，本轮不训练、不采购、不新增训练部署 |

具体约束：

- 先找现有可复用模块，不另建机器人、重复数据库、平行审批或新的运行时平台。
- 核实实际 Qwen 模型、接口、结构化输出和工具支持；不静默换模型、下载新模型或转用个人账户。
- 多 Agent 交叉投票不是 R1 必需；增加 Agent 数量不能作为正确性证明。
- 文件内容按不可信数据处理；服务端在取数前和写入前落实权限。
- **不读写任务发起人个人记忆、个人助理上下文或个人账户记忆。**
