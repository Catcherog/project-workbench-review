## 6. 追问、停止与阶段稿

至少区分以下五种状态：

| 状态 | 对应处理 |
|---|---|
| 已提供且可读 | 直接使用，不重复询问 |
| 已提供但暂不可读 | 说明具体读取限制，不写成没有该资料 |
| 已读记录缺字段 | 针对影响当前判断的缺口提问 |
| 记录相互冲突 | 并列冲突，核对对象、条件和版本 |
| 现有资料无法回答，需要工程验证 | 保留未知与建议，由专业人员决定后续验证 |

固定行为：

1. 先使用已提供信息，再回查授权范围内的资料；同类缺口合并提问。
2. 每个问题关联受影响的判断，说明为什么需要，不要求工程师手填全部内部字段。
3. 已明确重插线缆，就不再问是否重插；应查是否有能区分两项操作影响的记录。
4. 用户回答“不知道／没有记录／暂时无法提供”后，保留该状态；可以继续形成阶段稿。
5. 没有新的有效输入时，不重复追问、不自动催办、不循环生成。防循环保护可以实现，但不能用任意轮数代替业务停止条件。
6. 工程师可主动先生成阶段稿、暂停后补充或放弃本次草稿；恢复时沿用已有材料和未解决项。
7. AI 可以提出验证建议，不能编造样本量、已完成试验、负责人、截止日期或责任认定。建议值必须标注为待专业确认。
8. 需要其他数据提供者时，沿用已有获准联系流程；本任务不自动授权向同事、群或领导发送新消息。
9. 身份、权限、目标和版本缺失时，只阻止对应读取或写入；能独立进行的整理继续。

## 7. 文件内容和输出契约

### 7.1 日常五项基础结构

| 字段 | 内容 |
|---|---|
| 本次问题或决策 | 本次处理什么，或请别人判断什么 |
| 已知事实与来源 | 已观察、测量、完成或收到什么，对应哪份材料 |
| 当前判断与理由 | 证据支持什么，依据和适用前提是什么 |
| 范围、缺口与冲突 | 适用范围，还有什么未知或不一致 |
| 下一步与完成证据 | 接下来查什么／做什么，用什么证据确认完成 |

对象、版本、样本及共同条件可以集中引用，避免全文重复。负责人和日期只使用实际确定的信息。

首批文种的补充要求：

- **8D／异常分析：**在既有模板中分别处理现象、发生原因、流出原因、措施和效果验证，不增加一套平行表单。
- **测试报告：**明确判据、样本、条件和结果；区分通过、失败、未测、受阻；统计口径没有依据时保留未知。

### 7.2 每次整理必须交付

1. **可读候选稿或阶段稿。**优先使用既有工程可交付格式，不强制另建编辑器。
2. **关键差异及理由。**尤其列出结论范围变化、数值修正和重要删改。
3. **关键判断的证据索引。**能定位到文件及页、段、单元格或图号等已有位置。
4. **待确认项及影响。**已经回答或已查到的项不再重复出现。
5. **表达、证据、业务状态三项结果。**
6. **实际保存／挂载结果。**已写入时提供真实可打开对象及目标，尚未写入时不能显示已挂载。

页面优先展示工程师能理解的信息。模型参数、内部字段和检查程序名称留在诊断界面。沿用现有卡片结构，必要动作围绕查看、补充、阶段稿、采用／挂载及放弃当前草稿。

### 7.3 内部最小信息

复用现有实体和存储，按需要补充：

- 任务／事件标识、用户和项目范围、目标交付物。
- 来源和版本、原句、建议句、信息身份。
- 证据关系、结论范围及未解决项。
- 规则版本、模型配置版本。
- 实际业务状态来源。
- 用户采用记录和写入回执。

缺失值保留 `null` 及原因，不补成否、0、无、未执行或默认批准。

模型完成、文件保存、挂载、专业审核及节点完成使用可区分的记录；不要求业务系统因此新增五套状态字段。
