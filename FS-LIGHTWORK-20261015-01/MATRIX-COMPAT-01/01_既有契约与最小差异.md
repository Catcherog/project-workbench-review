# 既有契约与最小差异

这是**真实底表字段契约与候选聚合输出的比对**。没有原组件源码，不能将它表述为已经验证的组件内部接口。

| 项目 | 原矩阵已核实情况 | 个人周实际汇总需要的差异 |
|---|---|---|
| 人员 | 工程师字段为文本，演示值工程师甲/乙/丙 | 保存 `feishu-project-user-key` 命名空间与原字符串 ID；尚无到原文本人员的已核实映射，不能把真实人配给“甲” |
| 时间 | 月份文本 2026-10/11/12；页面下拉仅这些月 | 周列需前闭后开日期边界；T02 必须展示 9/14—9/20，不迁移源日期；9月月结果应同源聚合 |
| 工时 | 分配工时，计划口径 | 独立 actual 口径；不覆盖计划值、不相加；原小时不乘8 |
| 项目 | 所属项目选项＋总览项目记录ID关联 | 非项目不能冒充项目；项目数与事项数分别保留，原定位控件如何容纳非项目尚待组件验证 |
| 空值 | 明确0→已确认未安排；待填写→缺计划 | 实际明确0、未登记、失败、拒绝、分页未完、部分覆盖和待确认分别输出；不沿用“未安排”描述实际空值 |
| 明细 | 点击显示工程师月份各项目分配及关联项目总览 | 每一实际小计须携带原行定位、登记标识、原发生期和覆盖；不存在原总览关联时不猜配 |
| 刷新 | 原发布页重载可恢复读取演示表 | 本轮仅一次性真实读取及重复读取；原组件适配的刷新/缓存仍未验证 |
| 权限 | 原页面与底表在当前用户下可访问 | 当前 CLI 读取身份不等于每位看板查看者；没有服务端查看者授权，不提供真实明细的公共前端接口 |

实际读取的字段定义在 `evidence/matrix-fields.json`，27 条完整底表读取在 `matrix-records-before.ndjson` 与对应 manifest。母版设计在 `baseline/`，当前界面及关联表读回在 `evidence/`。

候选代码的行为：

- 按完整来源定位去重。相同服务端版本内容冲突、没有可排序版本而值不同，均保留冲突；本机读取时间不替代服务端版本。
- 多次完整快照先选择服务端最新版本，再归组；源行被删除不会因为把历史快照做并集而残留。重复分页行不翻倍，不按“同人同周同小时”删除不同合法行。
- 相同登记标识出现在不同来源定位时单列待确认，不宣称已证实跨源重复；未用父项/子项累计值加入实际明细。此范围仅一个源条目，不扩展扫描其他源。
- 同周记录直接计入；跨周缺分配依据不均摊、不全部放开始周；跨月的一周可在周口径计一次，但月口径待确认。
- 原始毫秒时间、ISO文本、原小时字符串、规范化小时、人员命名空间、业务归属和读取时间均保留。`group_uuid` 仅在完整联合源键中使用，不声称全局唯一或写入幂等。
- 实际聚合代码有周/月能力；这**不代表原组件已经增加周模式**。

最小接线尚未实施：把原组件的数据读取边界接到该候选输出，显式选择计划/实际与周/月，并复用原布局、筛选和明细。具体函数签名、字段适配和最小 UI 提示须拿到原源码再确定；本轮未凭截图重写界面。

权限依据：[飞书项目 OpenAPI FAQ](https://www.feishu.cn/content/60bl79n2)要求插件具备相应权限，调用 user_key 也具备空间权限。该文档只能说明核验要求，不能证明本矩阵的具体运行身份或查看者权限已经通过。
