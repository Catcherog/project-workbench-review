# 本轮执行指令

来源：指定聊天最新交接中的执行指令段；其内容与用户在当前开发对话直接提交的任务要求一致。此文件是执行指令快照，不是原始 exec.md 附件。用户随后要求先打包全部项目所需信息，在 Studio 新建项目继续。

```text
执行任务：FS-AGENT-GROK-POC-20261017-01 / R1。

请读取附件
《FS-AGENT-GROK-POC-20261017-01_R1_v1.0-exec.md》，
在已授权的隔离测试环境中实际实现、启动并验证，不要只返回另一份设计方案。

本轮目标：
先跑通“飞书输入 → Python 网关 → Grok CLI 真实推理 → 飞书结果”
的实际闭环，再逐步补齐第二个测试入口、附件、两人使用和简单恢复。

一、技术选择
使用 Python、lark-oapi、SQLite WAL。
不引入 LangChain/LangGraph、Redis/PostgreSQL、Jaeger/LangSmith。
Codex 只负责开发；运行时只调用 Grok CLI。
禁止调用 codex exec，禁止自动回退到 Codex、ChatGPT 或其他供应商。

二、先核对 Grok
确认本机 grok 的实际发行方、绝对路径、版本、非交互参数和认证方式。
默认候选是官方 Grok Build，但不覆盖或升级已有个人安装。
只在专用环境检查配置，不扫描个人工作区。
读取可用的默认 Grok 模型，首次成功后固定实际模型 ID 与 CLI 版本。
不擅自购买额度、升级订阅或复制个人登录凭证。

三、最小功能
实现私聊、测试群内 @、/menu、选择与切换。
先实现 /doc 和 /progress 两个合成测试适配器，不连接真实业务系统。
/doc 由模型整理内容，再由 Python 固定模板生成 Markdown 附件。
网关负责权限、上下文、路由、文件路径和发送目标，不能交给模型决定。

四、执行顺序
P1：真实 Grok 单次合成调用。
P2：飞书私聊到真实结果，成功后立即提供可操作入口。
P3：第二路由、群内状态、本人私聊详细结果及合成附件。
P4：两人同时使用、同人串行、过期过滤及简单重启恢复。

并发先按全局 2、每人 1 实现，实际先跑单路再验证两路。
排队最多 600 秒，执行最多 120 秒。
两路暂不可用时保留单路，明确登记并发未通过，不阻塞其他主线。

五、隔离底线
独立 macOS 服务用户，每任务独立 GROK_HOME 和工作目录。
关闭 Grok 记忆、子 Agent、搜索及不需要的工具和连接器。
不读取、修改、导入任何个人记忆、个人规则或个人认证文件。
Grok 自动保存的临时会话由服务清理，不假设 --no-memory 等于不落盘。
机器人上下文只保存在自己的 SQLite，按用户、群、Agent 隔离，
每条消息绝对 24 小时过期，不因聊天、复制或重试续期。
不得把真实机器人正文或个人资料贴回 Codex 开发对话。

六、开发原则
普通 bug 登记后继续；只修阻止当前功能运行的必要问题。
不要为了复杂审计、零 bug、全量回归或重构而暂停主线。
串话、越权、个人记忆访问和无法确认停止的进程，只暂停受影响路径，
不能带着这些问题继续真实调用。

缺少凭证、准确测试身份或必要管理员操作时，一次性列清，
继续完成其余可独立工作；不要重复询问已确认的设计原则。

七、交付
提供实际源码、无密钥配置模板、启动/停止方法、飞书操作步骤，
以及 handoff/00_当前交接.md。
只需最小任务记录与功能验证结果，不制作复杂审核包。
明确区分真实通过、模拟通过、未完成；不得用假执行器冒充真实 Grok。

不要改正式服务、扩大两人白名单、主动联系同事或上传公开仓库。
现在从核对隔离环境及实现 GrokCliProvider 开始。
```
