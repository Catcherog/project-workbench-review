## 离线复现

需要 Python 3.12 和原锁定依赖；本机使用现有 Python 3.12.13、pytest 8.4.2。不会安装依赖、读取生产配置、调用真实 Qwen/飞书或启动消费者。

在本目录执行：

```sh
python3 scripts/run_checks.py --source ./source --output /absolute/path/outside-package/fix1-check
```

先核对 `SOURCE_SHA256.json` 中 256 份脱敏源码，再复制到临时目录运行。完整 pytest 正确保留非零退出码 1；预期为 Harness 130 通过、会话含 R2 193 通过、原工程 611 通过/27 既有失败。`fixtures/reference_am/` 仅供历史安装构建检查使用，不能部署。

仅复跑附件五项：

```sh
python3 received-audit/run_regressions.py --source-root ./source --output /absolute/path/outside-package/five-check
```

## 原服务更新与核验

本轮使用 `source/am-harness-r1/scripts/install_fix1_runtime.py` 的流程：完整源码 SHA 校验、当前 HEAD 和干净已跟踪文件校验、后代关系校验、持有原模型跨进程锁、检查无在途业务、停止原唯一桥接、私有备份、快进、启动原服务。所有配置字节保持，没有更新或重启 Qwen/Ollama。

首次尝试因原模型锁忙在停止服务之前退出，随后取得原锁才执行成功更新。成功更新只重启原桥接一次，详见 `evidence/install-deferred.json` 和 `evidence/install-result.json`。

当前固定源码是 `d3e40b0d27517d75e850613c4eaecec107efa0ea`，不是旧 c968eca 或原 R2 起点。后续维护必须先核对真实当前 HEAD，不能把本包作为覆盖新工作树的部署源。审核副本包含脱敏字节；运行文件比对使用原源码 hash，不拿脱敏 hash 冒充原运行字节。
