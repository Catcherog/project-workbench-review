# 飞书沟通风格训练与任务对照方案

本轮将“表达像本人”和“事实与动作正确”分开建设。真实飞书消息用于抽象语气、信息顺序和追问习惯；实时业务事实继续从来源读取，不靠训练记忆项目状态。

## 数据链路

已有授权来源 → 本人发送文本 → 排除转发、附件、测试、机器人代发及命令 → 风格画像 → 虚构业务事实与任务 → SFT 候选／DPO 候选 → 事实与边界检查 → 样本评审 → 冻结 train / dev → 独立业务测试。

原文只在本机私有目录保留，遵守记录的原文期限；公开审核仅含生成器、数量、哈希与范围说明。当前画像由 26 段有限窗口文本支持：先交代具体进度，保留“如果、预计、尚未”，直接说明需要对方同步什么，日常跟进允许自然短句，采购、排期和正式文件保留数量与日期。不是每个场景都压成同一种短句。

当前候选集为 20 个模板家族，SFT 2400 条、DPO 1200 对，按家族分 train / dev。合成数量不代表人工确认或独立性。后续应增加真实任务类型与不同语义结构，避免只用换项目名和数字的近重复样本扩大训练量。

## SFT 与 DPO 的顺序

SFT 学习事实组织、追问方式、状态限定和自然表达；先验证小批高质量数据，再扩大。完整文稿、冲突归属和工具调用需另列任务，不能仅靠末端措辞样本代表整个助理能力。

DPO 从已验证的 SFT checkpoint 开始，参考模型固定为同一 SFT checkpoint。偏好对分开记录：同事实的表达好坏、遗漏关键事实、条件被改成完成、无回执声称已执行、猜测负责人或项目。偏好原因、来源和是否经本人确认均留存，合成偏好不能写为真人票。

本机现有成功链路是受控 MLX SFT pilot；既有 DPO 脚本使用 TRL，不能据此称为 Mac 上 MLX DPO 已跑通。正式 DPO 前仍需完成对应后端、参考模型固定、梯度／张量、保存及独立重载的验证。

新训练继续使用原资源协调器与唯一消费者，保留业务让路、停止未知核对和同一 Q8 恢复，不扩大内存阈值或通过改业务状态制造空闲。已有 R8 四题全部进入历史回归，不能充当新的未见测试。

## 任务完成与速度对照

新增独立测试应覆盖：项目摘要与来源核对、冲突和未知归属、正式文稿与缺项、已批准动作的执行与回执、跨天跟进、消息结果未知、来源失效及恢复。预先定义什么算完整完成，以及哪些缺项应澄清；模型返回文字、结构合格和业务完成分别统计。

固定同一组任务材料、来源快照、输出要求和动作权限。比较 MLX base、同 MLX + 新 SFT、同 MLX + SFT/DPO、生产 Q8、固定模型与推理配置的 Codex CLI，以及明确的组合。只有同运行时基座与 adapter 的配对适合讨论后训练增益。

每次记录：排队、准备资料、加载、首段可读结果、生成、复核、文档渲染、上传、平台回执与客户端展示。把完整成功率、严重错误、人工修改量与 p50/p95 并排展示；失败和超时保留在总分母。样本不足时给逐例结果和范围，不把四例 p95 当稳定服务水平。

## 组合调用与时间控制

候选方案包括单模型、按任务类型选模型、确定性检查失败后升级，以及每次复核。当前四题中，直接 Codex low 中位约 13.10 秒；Q8 候选再复核的分段相加估算约 22.39 秒。这批结果支持继续比较按需复核，不足以证明普遍采用双模型更好。

组合需预先给整个请求设截止时间，不能给两个阶段分别重置一份完整预算。接收请求时确定任务类别和时限；进入第二阶段前核对剩余预算与模型可用性；等待确认、模型超时和执行结果未知分别保留。第二模型只能核对原事实，第一模型的候选不得成为新事实来源。新代码已修复“复核器预检失败仍先调用 Q8”的浪费。

完整计时必须覆盖当前用户入口到最终可用结果；受理提示或首 token 不能代替最终完成。生产策略只形成绑定实测报告的选择提案，用户决定后再启用，原审批、来源和发送边界保持。
