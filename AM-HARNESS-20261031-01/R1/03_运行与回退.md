# 运行与回退

唯一运行入口仍是原 `local.qwen.feishu` 服务。后续 R2 当前仍保留 am_harness 四个功能开关均为 true，原业务配置和读取范围保留。新增库表使用 `am_harness_` 前缀；任务和回复绑定在原 gateway SQLite，来源投影 checkpoint 同库，焦点与元数据 trace 位于原服务私有 state 目录。

## 可使用的入口

- 明确单项目字段：`需求75谁负责`、`需求75的项目进展`、`需求75关键日期`、`需求75有哪些待办`。
- 复杂问题继续使用原自然对话。
- `停止当前任务`、`取消当前任务`；有多个任务时用 `取消任务 任务编号`。
- `更正当前任务：新的要求`；或 `更正任务 任务编号：新的要求`。

原“取消”“先别发”等待批准动作控制语义保留。任务更正和停止不会替代正式批准；已提交操作、原文档后台作业与已启用提醒按各自原状态处理。

## 操作要求

`source/am-harness-r1/scripts/install_runtime.py` 只适用于原 Studio 本地 Git 工作区。使用前必须核对最新 HEAD、并行修改、在途任务、原消费者及模型状态；传入完整 40 位源码 SHA。它会私有备份原配置和数据库，仅快进代码和改变 am_harness 开关，再启动原服务。审核快照不能直接用于真实部署。

按 `fastpath → full` 分步启用。运行核验使用同目录 `verify_runtime.py`，核对实际加载字节、配置、连接、锁、模型 pin、600 秒身份、台账写入开关与 lane 状态。

回退时先停止新 Harness 准入，等待已知 worker 返回；已处于 sending/unknown 的业务按原记录核对。停止不确定或 lease 隔离不能直接清状态。原 provider pause 保持原流程，不启动第二个模型通道。

仅快查询安装器保留 `installation.restore()`，并检查 callback 仍由本次安装持有。完整运行层的生产回退尚未演练：须先排空/核对在途与未知动作，并保留失效历史过滤，或在原保留期限届满并清理后再恢复旧历史读取。不能只改四项开关就宣称完整回退已验证。保留数据库、幂等墓碑、批准与回执；不能用旧数据库整体覆盖当前业务。

状态 CLI 只读：

```sh
PYTHONPATH=source/FS-AGENT-GROK-POC-20261017-01_R1_Studio/src \
  python3 -m am_harness status --database /absolute/path/to/gateway.sqlite3
```

真人、手机与确切业务挂载目标验收仍待执行。新增工具并行、精确 tokenizer 预算或长文批次恢复，应分别加入有来源的验收记录，不由当前通过项推定完成。
