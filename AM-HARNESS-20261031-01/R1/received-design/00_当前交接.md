## 一、原始目标与本轮决定

基于既有 AM 机器人框架，对 OpenAI 与 DeepSeek 最新 harness 机制做研究，并落实可提升之处。当前落地选择是保留原 Python/AM/Qwen 架构，增加确定性查询、持久任务生命周期、非阻塞控制、版本 fence、来源上下文、阶段复用、可观测性。

优先解决：明确项目字段查询不必每次经过模型；运行中的任务能接收更正/取消；取消不丢失实际已提交效果；同消息不重复执行；旧来源与旧权限不能被摘要或缓存延长。

这不是迁移到新的机器人框架，也没有要求更换模型。所有新增组件均为 stdlib Python；原 AM 的业务权限、预览批准与唯一 outbox 继续是权威。

## 四、Codex 需要完成的具体工作

### C1：最新树合并与 Phase 1（优先）

将 engine 增量合入当前代码，并接 `install_fastpath_only(existing_bridge)`；保留模型、provider、consumer 和原 outbox。先在原环境验证四字段、歧义回退、重复消息和原功能。该切片有现成实现，无需从头重写。

### C2：真实入口三分流

在 `AmSelfService.ingest` / `QueryMixin.pump` 的既有消费链中接 control、独立 read、durable turn 三条准入；控制不能再被同用户 future 阻挡。保留原身份与来源读取流程、原有 I/O 并发边界，防止同 inbox 事件同时走旧 conversation future 和新 worker。

### C3：真实 context resolver 与持久 worker

实现新鲜 Scope/grant 校验及 `bridge._active` context manager。任务 snapshot 不能替代授权。接原业务循环调用 `TaskRuntime.run_once`，为停机、心跳失联、lease 隔离提供可观察状态。继续调用旧 ModelCoordinator，不清 provider pause，不自动重试 unknown。

### C4：原 outbox 的同库提交与派送

把 DurableStore 放进原 AM outbox 所在 SQLite，复用传入事务 `conn`，补好原 outputs/event/grant/thread 记录，然后默认使用 `verify_legacy_binding`。纠正后的来源是实际控制消息，内部 engine event 独立；使用 `deterministic_publication_key(run)` 避免旧 key 冲突。在原 pending→sending 事务中接 `before_dispatch`；保留原当前权限与回读检查。

### C5：正式业务动作的真实提交边界

逐个接原发送、提醒、文档提交等 action reservation，保持原 version / accepted_hash / receipt / reconcile。引擎前置 guard 不等于原子网络提交。完整接线之前，仅将明确读任务或无外部效果任务纳入新可取消路径，不宣称覆盖所有正式动作。

### C6：上下文、checkpoint、只读并行与真实打点

接上已给出的 `FencedHistoryStore`，将原事实和历史映射为组件所需的 source/version/TTL 状态；为真实阶段定义可复用 key；校准 Qwen 包装模板与 tokenizer 预算；仅把经检查的独立 read 工具加入并行白名单。把 first_useful/final 绑定实际可读/投递边界，不用排队提示替代。

### C7：同一最终版本验证与回传

补跑原 fs_agent pytest 全套、真实 Qwen/飞书矩阵、实际同事和手机端交互，按相同模型/机器/来源/冷热缓存做 baseline/candidate 成对比较。最终所有证据对应同一 commit；不能拼接多个开发阶段的通过次数声称最终全通过。

回传继续使用既有 review repo，建议目录 `AM-HARNESS-20261031-01/R1/`，至少含当前交接、实现差异、原环境测试、真实模型与飞书证据、剩余项、固定 commit 和文件 hash。仅在现有权限允许的范围内回传，不自动发布生产或发送给新对象。

## 五、必须继承的约束

1. 复用原唯一飞书消费者、原模型通道与 ModelCoordinator；不另起第二个机器人消费者。
2. 不替换当前 Qwen，不自动清 provider pause / STOP_UNKNOWN，不从未知执行状态直接重试。
3. 身份 TTL 600 秒仍按固定飞书 ID；管理/执行仍走原强校验；`ledger_write=false`。
4. 五元 Scope 和项目可见范围贯穿读、上下文、工具和派送；群引用与 thread 不串用。
5. 原预览展示、版本、accepted hash、批准、回执、幂等和 unknown 对账保留。
6. 不把任务控制当批准，不把摘要/缓存当事实或权限；来源 TTL 不延长。
7. 不接入个人账户记忆，不扩大现有业务资料或消息收集范围。
8. 包内 baseline 是复现材料，不覆盖当前 Studio 文件；保留并行变更。
