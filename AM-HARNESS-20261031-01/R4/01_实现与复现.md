# R4 实现与复现

R4 从当前有效源码 `73c1f9e11ec8b1ea9c3e36060a2522fab3676480` 增量实现，保留 R3 后续跟进功能。收到的两份宿主 overlay 在应用前与 R3 基线核对；没有盲目覆盖已变化的源码。

## 三个限定补修

来源 `quote` 非空时，必须与完整 typed value 一致（仅忽略首尾空白）。否定、预计、阶段范围、负责人实体冲突拒绝投影并保留原回复；不凭关键词或相似度证明等义。原样的否定和预计字段仍可通过。

`closed_query_support()` 将原有闭合问法绑定到唯一项目、被询问字段、required claim、同一项目完整读取及显式读取身份。缺字段、跨项目拼接、同名歧义或错误读取绑定保留 partial 与目标未完成说明。这个有限语法不承担通用复合意图识别。

`needs_confirmation` 与 `knowledge_candidate` 当前保持原 UI 路径、零表达调用，不取得新语义通过记录。实际采用 canonical/candidate 时，原 outbox 事务要求最终 kind=text、artifact=None、body 与 prepared.text 相同且哈希一致。正文删改会令 outbox 与投影共同回滚。未统一“查询事实＋批准预览”的最终消息合同，也未扩展到卡片或附件。

## 表达、数据和 MLX 接入

`NaturalSurfaceVerifier`、transport、review、silver 和 Codex 原始工件校验已合入原 `am_style`。自然语法仅在本轮隔离实验显式开启，生产默认不变。

新增 `generate_r4_projected_seeds()`，从合成宿主输入生成新的 ID/frame。测试开始时间与时长使用 `start_and_duration`；单独 start_time 与 duration 也分别验证。原 R3 生产函数、gold prompt 与旧 frame 保留。真实业务中的任意模型追问仍缺可信 typed gap 接口，原 projector 对其继续回退；本轮没有声称全面接通业务自然追问。

训练模块与运行模块在原工程不同目录，prompt builder 指纹已改为实际导入文件路径。新解释器继承绝对 PYTHONPATH。没有改基座、数据门槛、学习率、步数、内存或诊断容限来通过检查。

## 脱敏复现

审核仓库在固定提交下，按 R2-FIX2 → R3 → 已有跟进 R1 → R4 四层指纹重建。`source/` 仅为本轮59文件增量，不是完整生产安装包。

```sh
python scripts/reconstruct.py --review-root /absolute/project-workbench-review --output /absolute/new-r4-rebuild
python scripts/run_checks.py --source /absolute/new-r4-rebuild/source --output /absolute/new-r4-checks
```

使用原 Python 3.12 测试依赖环境。重建表达检查需将 `source/am-conversation-r1/src` 与 `source/am-style-r3` 加入 PYTHONPATH，运行 `python -m unittest discover -s source/am-style-r3/tests -v`。测试不请求真实平台或模型。

实际模型运行使用原消费者验证队列；唯一发送通道与原模型协调器不变。`terminal-real-probe.json` 的任务模型是脚本夹具，只在终端表达阶段调用真实 Qwen；不能写成真实业务全链路验收。
