## 六项补修

| 项目 | 实际实现 | 证据 |
| --- | --- | --- |
| A01 目标完整性 | 同项目各事项独立身份；明确创建、保存、提醒、发送及精确对账分别核对。匹配对象、事项文字及本人提醒目标，一条回执不能满足两项；未完整解析保留原请求，已识别未办事项仍显示。成功调用缓存、未知调用阻断重放。 | test_harness_r2_fix1_audit.py 中 same_project、compound_reminder、real_loop、single_explicit_matter、personal_reminder、unresolved_clause 等用例 |
| A02 真实结果 | 文档工具实际返回内容与采用指纹，按草稿、版本及本次请求指纹核对；ready 本身不等于采用。只读 reconcile_send 保留已核执行状态、真实回执及必要呈现块；核对动作成功不再被通用读取分支降级。缺凭据时不保留成功措辞。 | adoption、real_adoption、readonly_reconciliation、reconcile_read、invalid_adoption_receipt 用例 |
| A03 身份期限 | 身份缓存期限退出内容有效期计算。原授权守卫继续续验；呈现保留内容及来源最早期限，续接也继承原目标期限。动作提交后续验、保存、回读及仅提交一次得到宿主测试覆盖。 | identity_renewal、real_committed_followup、renewal_never_bypasses、goal_resume 用例 |
| A04 shadow | 观察路径关闭新模型协议及任务修复，不改原工具选择和实际正文；冻结观察输入。离线 replay_frozen 产生实际候选并保存判定，不投递、不执行工具。 | legacy/shadow 同输入轨迹、offline_shadow_replay 用例；真实模型回放单列 |
| A05 清理 | 投递投影的生命周期维护不再依赖表达开关。原 Store 在没有投影对象时也清理已存在附表；会话呈现、目标与中断表保留到期清理。 | legacy 重启清理用例 |
| A06 投递终态 | 原 outbox 仍是发送权威。附表由同库触发器和启动对账同步，统一联表视图提供原状态；未知、拒绝、过期及重启中断不长期显示 queued。核验状态仍要求消息和正文一致。 | outbox_terminal 参数组；本人旧模式查询附表/主表同为 sent |

## 其他实际接线

- GoalJournal 已进入主循环，独立由 runtime.goal_tracking 控制；在原会话库保存目标、进度、调用结果、执行中占用及原期限。续接重新检查当前项目范围和原全局来源版本，成功步骤不再次执行。复杂语义、专业异步任务和所有取消/更正组合尚未达到通用续接验收。
- EvidenceBundle 实际用于项目查询和文档取数，后者调用同一资料服务并保留相同 bundle ID；以当前项目目录身份为准，旧文档项目身份作为映射记录保留，未改写既有草稿。模板、标准、项目事实及原采用/保存/挂载门不混合。
- 精确依赖在读取边界收集，并查当前本地来源记录作影子比较。内容变化、撤权、删除、到期、缺失依赖和集合变化均有测试；平台继承权限及集合完整性未证明时返回 indeterminate。原全局来源守卫仍决定是否放行。
- 生产语义规则返回 pass / reject / indeterminate，检查有序命题、否定和模态限定、引用内容覆盖及来源归属；疑似多主体混用、未支持的改述和推断不通过。逐字来源投影、保护块、canonical、fallback 不进入自由表达成功分子。
- 必要追问按具体缺参生成，已实现本人提醒时间、事项内容等受限路径；未知动作建议仅限先核对。不能从当前能力之外提出可自动执行的承诺。
- 新协议 am-response/2.1.0 使用请求内数字引用与短快照标识；宿主保留完整事件、任务版本、事实及 hash。提案必须对应发起该次模型调用时的冻结结果，结果变化后拒绝旧提案。旧格式记录可读，不重写已保存正文。

登记工具静态矩阵见 evidence/adapter-matrix.json。synthetic_notify 是测试辅助工具，不是原生产注册入口；登记覆盖也不等于每个真实业务分支均验收。

## 模型预算与本次恢复

固定主循环评估暴露一次真实原模型通道 stop_unknown：任务到达 120 秒总预算时，最后一次 HTTP 推理请求仍未取得完整返回。保留了故障样本，评估自动停止后续入队，没有重试未知请求。

随后等待原服务自动卸载模型，核对原 HTTP worker 已停止、模型列表为空、推理进程不存在、原 Ollama 服务 PID 和模型摘要不变。在原受控维护窗口保存原未知标记，通过原 resume CLI 恢复模型通道；未知输出仍为 unknown_not_replayed。没有重启、替换或主动卸载 Qwen/Ollama。证据见 evidence/model-stop-reconciliation.json。首次恢复调用入口不符，已回滚暂停标记并保留记录；成功恢复记录与首次失败分开。

桥接现在要求下一次模型调用至少剩余 60 秒可用预算；原单轮 120 秒上限保持。不足时不发起新推理，保留已提交结果并明确未完成部分。此阈值用于避免已知短预算派发，不保证任意模型请求都不会超时；真实停止状态不明仍进入原隔离及对账流程。

## 固定测量后追加的续接修正

正式 288 条观察固定在源码 e86a443367c5bfbd980103481a14039334dd6280。补核发现 GoalJournal 使用的原 action_metadata 只返回元信息，不含 result，导致已批准动作不能恢复到目标完成状态。该反例保留在 evidence/goal-terminal-reproduction-e86.json。

最终源码 f767cea93444217d40a52bea6330f51434f3ce27 改用原 get_action，保留所有者、来源和会话范围检查，并核对工具、参数和预览版本。核实结果同时恢复到目标单元及调用缓存；重复读取不把成功结果降回待批准。未知状态继续阻断重放，关闭的外发动作不新建替代动作，明确失败的本地步骤仍保留原规则下的显式重试。只读对账结果不作为外发执行的别名。

这一增量增加 11 项反例，完整工程变为 781 项（754 通过、27 项既有失败）；新增审计检查累计 74 项，已包含在 781 项中。旧失败逐项一致。正式模型统计没有改标为最终源码运行，补充 6 条模型观察另列；两版表达协议、模型入口、语义校验和 adapter 的相关文件字节一致。版本差异与覆盖限制见 evidence/post-measurement-change.json。

非空 shadow 工具路径另有一组双模式核对：同项目两条跟进，两模式各执行两次原工具、两轮主调用，展示正文保持为该次执行的原工具回复。原 Qwen 的离线回放真实产生候选，因 unaccounted_claims 被拒绝；回放期间没有业务调用和投递。该观察不是自由表达成功。
