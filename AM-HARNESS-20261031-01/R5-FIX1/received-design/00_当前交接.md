## 3. 补丁边界与接口

补丁只涉及 R5 的独立测试执行前置校验、pilot 接入、CLI 参数及相关回归。完整变更文件、原始文件 SHA256 和补丁 SHA256 见随包清单。

训练计划可以在缺独立测试时准备，元数据预检继续独立运行。生成可执行 trainer argv 之前必须重新读取以下三份真实文件：

1. 已冻结的独立测试 bundle。
2. 绑定精确 `case_manifest_sha256` 的未用于调参声明。
3. 与声明 `source_evidence_sha256` 相符的原始声明证据。

执行门禁核对冻结内容与实际 prompt 的一致性、全部 `sealed_test`、未公开声明、本次实际 gold 快照、train/dev 场景组和近重复排除，以及文件和内容哈希。缺失、变更、重叠或不可读时禁止产生训练启动命令。旧计划可以做元数据检查，但没有新绑定就不能执行；缓存中的通过标志不能覆盖新鲜回读。

原件哈希只证明“读取的文件和被绑定的字节相同”，不会认证评审者身份或自动证明业务场景独立。声明的来源与独立性仍须由原机实际记录支持。合成单测中的声明和人工标签仅为测试夹具，禁止复制到实际训练数据。

独立测试通过也不代表已取得资源窗口。原 R4 trainer 仍在原协调锁内检查启动前24 GiB、运行中5 GiB、swap增量、业务抢占和生产身份。原 R4 代码、固定源码哈希、超时、训练步数、数据门槛和生产开关都沿用原约束。

预检输出与退出码按以下口径读取：

| 字段或命令 | 精确含义 |
| --- | --- |
| `metadata_ready` | 原输入、源码和运行环境元数据是否通过；不包含资源锁与模型加载 |
| `execution_gate.status` | 独立测试输入门禁的 `passed` 或 `blocked`，范围明确为 `independent_holdout_inputs_only` |
| `resource_gate.status` | 预检始终为 `not_checked`，由原R4执行入口在锁内检查 |
| `ready_for_launch` | 预检保持 `false`，表示该预检不签发资源放行；不要再将旧布尔字段理解为训练已允许 |
| `pilot-preflight` exit 0 | 仅表示元数据预检通过，独立测试门禁仍可能阻塞 |
| `pilot-command` / `pilot-execute` | 重新核对输入和独立测试；失败 exit 2。通过才允许进入原R4资源检查 |

有效材料使输入门禁通过后，命令生成仍不加载模型。执行路径在元数据探针前后比较同一计划和同一门禁绑定；预检期间完整重绑另一套有效计划也不能沿用旧探针结果。
