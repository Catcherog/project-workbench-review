# 发布与远端回读

## 本轮实际状态

代码、设计、补丁和云端验证已经完成。尝试通过现有GitHub应用创建新R6审核树时，GitHub API返回：

```text
403 Resource not accessible by integration
```

这是GitHub接口写入权限阻塞；不是自动审批拒绝，也不是测试失败。此次调用没有返回新tree／commit，未创建分支或修改其他任务目录。本轮没有新的固定审核URL，也没有声称远端逐文件回读完成。

完整包及校验清单已准备。Codex可在原机使用已经授权的Git凭据完成发布；无需重新编写本轮功能。

## Codex发布步骤

1. 在原机确认目标是既有 `Catcherog/project-workbench-review` 审核仓；读取当前远端main，保存准确基线SHA。
2. 使用隔离worktree或新分支，从当前审核基线增加 `AM-HARNESS-20261031-01/R6/`。保留所有其他任务目录；不要覆盖已有R6内容。如当前已有R6，先读取并协调追加路径。
3. 将本包整个顶层目录的文件原样放入R6，包括 `00_当前交接.md`、docs、files、verification、补丁和manifest。确认Git待提交列表仅在R6范围，提交并推送本轮审核分支。不要把原机私有材料、数据库或凭据一起提交。
4. 固定推送后的完整40位审核SHA。对该SHA进行独立HTTP逐文件回读，并比较其他任务的Git blob集合：

```bash
python3 /absolute/package/tools/verify_remote.py --package /absolute/package --commit <实际40位审核SHA> --base-sha <发布前审核基线SHA> --receipt /absolute/private/r6/remote-readback.json
```

脚本只读取公共审核仓，并把结果写入指定本地回执；不创建提交、不发消息。其manifest先核本包所有文件，再按固定SHA读取所有远端文件，最后核对R6之外的文件未增删改。失败不会报通过。

5. 确认 `all_files_match=true`、`remote_task_file_set_matches=true`、`other_task_directories_unchanged=true` 后提供实际固定审核入口。回执存于私有结果目录或本轮原机回传附件，不能在读取后改写同一固定包而继续沿用旧manifest。

原机实际源码SHA与这个审核SHA分开记录。本轮开发包的旧权限阻塞记录是历史事实；后续成功发布后，在Codex的新回传中记录新的完成状态，不伪造本轮未发生的上传或回读。
