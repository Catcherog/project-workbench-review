## 3. 四项残留问题

### F01-a / P1：知识库提交结果不明被掩盖，任务仍成功并释放执行通道

**实测路径：propose_knowledge、record_report。**

复现沿实际 local 工具，在本地知识数据库已经 COMMIT、gateway 事务尚未完成时注入中断。故障位置与本包已有 save_work_note 未知提交回归相同，没有伪造业务成功结果。

两条路径均得到：

    知识记录 = 1，状态 candidate
    本地提交回执 = 1
    reservation = reserved
    worker = completed
    run = succeeded
    lane = idle
    模型调用 = 2；第二次提示含 TOOL_UNAVAILABLE

本地记录确已提交，但统一任务状态却表示成功，仍未对账的占用被留在后台。已有占用不能据此认定安全完成；本次没有观察到自动重放，但错误状态和通道释放已违反原未知结果隔离要求。

根因链：

1. am_harness/reservation.py 的 guard_local_database 在 gateway 提交失败后正确抛出 HARNESS_LOCAL_COMMIT_UNKNOWN。
2. am_conversation/knowledge.py 的 _transaction 在本地 COMMIT 后仍无条件 ROLLBACK。
3. SQLite 报“cannot rollback - no transaction is active”，覆盖原未知提交异常。
4. engine.py 将该 SQLite 异常转为 TOOL_UNAVAILABLE，继续模型循环并正常完成任务。

定位：source/am-conversation-r1/src/am_conversation/knowledge.py 159—177 行；source/FS-AGENT-GROK-POC-20261017-01_R1_Studio/src/am_harness/reservation.py 139—149 行；source/am-conversation-r1/src/am_conversation/engine.py 449—453 行。

**最小修复要求：**

- 仅在仍有活动事务时执行回滚；清理失败不得掩盖决定执行状态的原异常。
- 保留已提交记录、本地回执及待对账占用；任务进入 unknown、lane 进入 quarantined。
- 未知提交后不得继续下一轮模型/工具或自动重放，按原对账规则处理。
- 覆盖 propose_knowledge、record_report，并定向核对同库 revise_knowledge；不回滚已经真实提交的记录。
- 既有 save_work_note 回归继续通过。正常成功路径和提交前回滚仍保持原语义。

对应新增测试：test_unknown_knowledge_commit_preserves_quarantine 的两个参数化场景。

### F01-b / P1：直接“批准知识”绕过本地任务绑定，停止后仍提交

复现：

1. 通过原宿主保存合成知识候选，状态 candidate。
2. 提交“批准知识 <真实候选 ID> v1”。
3. 在 knowledge.approve 实际调用前，经原入口处理“停止当前任务”。
4. 继续原批准调用并回读。

结果：任务 cancelled，worker stale，回复未发送；知识却从 candidate 变为 approved，该任务 reservation 为空。

这是业务提交没有受取消保护，后置检查只抑制回复。已通过的跟进恢复回归不能代表这条直接控制入口也已受保护。

根因：engine._control 直接调用 knowledge.approve，没有经过 execute_local；guard_local_database 在 _local 没有绑定时直接按普通调用继续。

定位：source/am-conversation-r1/src/am_conversation/engine.py 198—207 行；source/FS-AGENT-GROK-POC-20261017-01_R1_Studio/src/am_harness/reservation.py 122—125 行；source/local-qwen3.8/feishu-bridge/am_harness_host.py 373—377 行。

- Harness 活动任务缺少绑定时必须拒绝；保留非 Harness 原有合法调用方式。
- 取消先于提交保留 candidate；取消晚于真实提交保留 approved 和提交记录。
- 定向验证更正、原业务版本条件及缺绑定拒绝。
- 保留“按指定版本批准知识”的原交互，无需增加批准步骤；仅补前后 checkpoint 不足以修复提交窗口。
