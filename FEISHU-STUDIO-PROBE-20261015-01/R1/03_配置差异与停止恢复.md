# 配置差异、停止与恢复

起始：正式工作台 2.18.1 正在运行，现有飞书应用已发布，1 个上游长连接和 2 个本机正式消费者。应用可用范围仅参与者 A。

本轮变化仅为新建独立目录、合成文件、私密证据、便携源码和本地运行状态；执行 3 次受限 Codex。曾通过同一现有总线进行 1 秒 `select(false)` 空消费，正常超时退出。未另开上游 SDK 连接，未切换订阅方式、修改回调或全局配置，未改正式源码、业务状态、调度、自启动或系统电源策略。

正式业务库仍由原服务自行运行，不以全库哈希“不变”证明本轮非干扰；本轮程序未获得该库路径，也未调用其写接口。证据仅支持本轮临时消费退出、原 PID/消费者保留及服务 ready，不扩大为全天候可靠性。

## 在 Studio 接续

1. 解压本包到独立目录，重新读取本任务交接。不要覆盖正式工作台或复制正式业务库。
2. 确认实际机器、Node 22+ 和 Codex 版本；复用该机器合法登录，勿将旧机器的认证文件、飞书密钥、全局 `.codex` 或事件总线缓存塞进迁移包。
3. 按 README 运行无网络的路由回归与直接系统隔离测试。`PROBE_CODEX_BIN` 指向该机器已安装的 Codex 可执行文件。
4. 若获准执行本地模型探针，仍计入本轮调用上限；包内 `evidence/round-budget.json` 记录已使用 3 次。迁移后用 `node src/import-budget.mjs` 将历史次数导入新的本地计数库，避免从 0 重新计算。本轮剩余上限为 17 次，不等于授权自动消耗完。
5. 先完成 B01—B04 的审核与修复，再决定是否启动新的真人窗口。现阶段运行 `node src/start.mjs` 会明确退出 2，不连接飞书、不发送消息。

Studio 上不能直接启动新长连接：原机器的正式接收服务仍可能在线。必须重新核对远端在线连接与原消费者，并经正式批准确定受控转发或迁移方案。当前包不包含自动停止旧机器服务的逻辑。

## 停止与残留

本轮所有临时消费和模型进程均已结束；无定时任务、无常驻监听、无未发出的邀请。正式服务无需恢复。

保留的 `runtime/` 为本轮合成数据、计数库和执行证据，`private/` 为内部源依据；都不提交公开仓库。迁移 ZIP 使用白名单，仅含脱敏源码、文档、证据和配置占位符，不含这些目录。源码删除不属于本次执行；如需清理，先保留审核证据和调用计数。
