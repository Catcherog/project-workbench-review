# 本地协议验证与复现

## 运行

Node 22+ 且支持 node:sqlite；实际 Node 24.21.0/macOS，使用标准库，无新增 npm 依赖。

```sh
npm run demo
npm test
npm run test:baseline
node tests/verify-demo.mjs
```

以上默认只启动本地合成适配器，真实模型与平台发送均为 0。演示输出在 evidence/demo.json 和 demo-summary.json；测试输出与逐场景记录在 delegation-tests.tap、test-results.json。本机 runtime 保存本轮合成账本和终止记录，公开包不含 runtime。

演示依次跑直接确认与机器人转问两条路径，每条新建明确的合成请求和独立账本。重启防重用例使用同一个账本，不靠删库复现。重复运行演示生成新的合成目录，不覆盖旧的未知记录。

## 结构与信任边界

- codec：规范化 JSON 与 Node 标准库 Ed25519；签名覆盖完整操作对象，可信公钥从控制器配置获取，忽略/拒绝正文携带的替代根。
- policy / grant：固定的一名合成工程师、两个不同服务身份、一份摘要和一个接收对象；分别核对读和披露权，检查不可变预览及独立本人确认。
- store：SQLite 请求状态、一次性 nonce、计数与日志；在外部派发前持久标记 DELIVERING，重启遇此状态转为未知。
- adapter：engineer / human / receiver 独立短期进程，通过 stdin/stdout 序列化往返。工程师进程只拿自己的临时签名私钥；确认进程使用另一把私钥；接收器验证后持久接收并签回执。
- probe：独立代理入口，与原真人 broker 门禁分开；控制器只中转和校验。原 p2p/user 检查未修改，不把 bot 改标为 user。
- runtime：直接复用固定 FIX3 的受管进程、终止账本与 owner 规则；取消、停止和退出检查有界。无长期服务、公网端口或平台事件消费者。

本人确认适配器由测试控制器自动驱动，所有事件均为 synthetic，不代表真人已批准。测试控制器拥有各测试密钥以构造正反例；这些本地同账号进程不构成 OS 级密钥隔离证明。临时私钥没有写入公开材料。

本轮“意图识别”是确定性模板补全，不是自然语言模型能力测试。两轮合并澄清后仍缺项即停止；身份自述、紧急指令和反弹消息不会修改规则。

## 验证矩阵

| 类别 | 实际检查 |
|---|---|
| M01/M02 | 两条完整确认路径；不同适配器 PID；签名、摘要、对象、请求及接收回读一致；每请求交付一次。 |
| M03 | 本人拒绝、未回答澄清、未确认、迟到确认；可控时钟推动超时，无交付。 |
| M04/M05 | 错签名、未知/撤销服务、正文替换信任根、跨租户、裸跨应用 ID、错应用、同名异主体；读取和交付为 0。 |
| M06 | 有效机器人签名加 approved=true/引文，以及用机器人密钥冒充本人签名；独立批准验证失败。 |
| M07/M08 | 有读无披露、原始日志、任意路径、其他接收人或能力；授权检查先于资源读取。 |
| M09 | 确认后更换正文、对象、操作、用途、版本，及底层摘要字节改变；不交付。 |
| M10 | 批准后撤销绑定/委托/披露权或改变规则版本；执行前拒绝。 |
| M11/M12 | 过期、nonce 重放、同 ID 不同载荷、并发重复、同账本重启后重复；不追加副作用。 |
| M13 | 接收已提交但确认回执丢失：DELIVERY_UNKNOWN；确认收到但回读失败：LOCAL_RECEIVED_UNVERIFIED；均不盲重发。 |
| M14/M15 | 领导/紧急文本无效、反射消息拒绝、澄清最多两轮；无机器人自动反弹。 |
| M16 | 处理中停止取消、停止后禁止新启动；退出未知保留 owner，实际 OS 不存在检查后显式对账；settled 后 stop 前迟到 spawn 拒绝。 |

新增 14 项 Node 测试，内部生成 39 个场景报告；两个完整演示另列，不累加成更多测试。继承 FIX3 的 84 项回归只计一次，其导入文件未改。测试私有密钥不进入报告；正常演示的公开信任根可用于独立验证签名和请求/内容映射。

保护性计数明确区分：summaryReads（服务准备/执行读取）、rawLogReads（服务未授权日志读取）、deliveryTools、dispatches、readbacks。测试素材创建和签名适配器启动不属于敏感资料工具执行；实际适配器启动及 PID/退出记录另列，避免“工具调用 0”被误读成根本没运行进程。

## 收口与残留

正常进程组全部确认退出。退出检查不可用反例使用受控检查替身，不制造长期失控进程；当时的 owner 和未知记录保留，随后通过真实 OS 查询确认进程/组均不存在再显式对账。原未知停止回执保留，不改写成最初就安全。

runtime 保留合成 SQLite 请求/接收账本与终止记录，private 保留必要输入与只读元信息；均不发布。不安装自启动或无限等待，不清理别人的进程。停止调度上限为 4 秒，单次普通本地 IO 上限 5 秒；这些是软件边界，不保证失去响应的操作系统能实时终止。

公开数据只包括合成转录、测试公钥/签名、原始输出和脱敏摘要。输入帧指纹包含未公开的测试密钥与本地路径，用于本机追踪，不能从公开包重建原 stdin；公开签名与业务内容仍可独立验签。
