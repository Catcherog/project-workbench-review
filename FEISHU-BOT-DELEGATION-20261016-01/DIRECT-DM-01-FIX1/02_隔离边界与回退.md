# 隔离边界 业务影响与安全回退

**当前方案未安装；不能同时承诺“同会话任意普通文本自动继续入库”和“任意迟到无引用测试回复永不入库”。** 两种消息在平台元信息上可以相同，代码不能凭语义猜测获得可证明的区别。

## 本候选具体隔离什么

仅固定 app/tenant、采集操作者及两段登记的机器人 p2p 会话。从首次登记时刻起，该两段会话的新消息持久暂存；正常业务消息也包括在内，不作为正式资料、自动输入、预算重试或自动回执的来源。已登记请求 ID、消息 ID、parent/root 引用继续隔离；其他会话、同一参与人与其他人正常私聊及登记前历史保持原有路径。

五分钟只约束确认有效期；被动隔离没有自动到期。`stop()` 只停新执行，并追加停止记录，不撤掉会话边界、去重、外发意图或未知结果。worker 离线或结果不明也不会转回业务。

## 明确冲突与最小选项

A：未来具体批准后，以这两段机器人私聊作为测试接收边界。用户必须接受这两段会话的新业务输入暂不自动入库。结束后仍保留被动隔离；普通业务可先沿用不在边界中的既有渠道。需要恢复这两段会话的自动采集时，须单独评审迟到消息与正常消息的处置方案，当前代码没有危险的“一键清空/解除”入口。

B：如果这两段会话必须持续自动接受正常业务，则当前单应用、同会话约束下无法给出所要求的零污染保证。保持真人测试关闭，另行批准可证隔离的接收边界后再实施；本轮不自行增加应用、成员、群聊、权限或改造原正常输入。

**不建议把 A 在未明确接受影响前装入日常输入通道。** 这不是要求工程师“务必引用”来弥补隔离漏洞，也没有默认给用户新增日常操作。当前仅在合成副本验证 A，正式会话不受影响。

## 持久接入和回退影响

登记前可撤销未启用的候选，普通安装保持原有 version 2。登记时以完整正式库的 setting 和独立 sidecar 固定 ledger 位置、身份和请求哈希，数据库 capability version 变为 3。该变化发生在本轮临时库，尚未触碰正式数据。

登记后即使启动环境变量丢失，仍从持久登记加载。配置改指、账本缺失/损坏、同路径替换空库、独立标记或数据库记录缺失，都拒绝启动。旧 host 在消费者开始前因不支持 version 3 被拒绝。这个保护意味着异常可能阻断**整个工作台服务启动**，是未来安装需要单独批准的可用性影响。

安全停止是关闭专用执行，继续保留被动隔离和原未知意图；不能通过降数据库版本、抹掉登记、恢复旧程序加旧业务库或清空账本来回退。候选未实现自动解除历史隔离，也不保证同账号有权任意改写程序和所有数据时的 OS 级防篡改。回退/恢复应由后续经审方案处理，不能把恢复业务通畅作为默许污染的理由。

原失败用例保留在 `dm/tests/direct-dm.test.mjs`，默认 `npm test` 返回失败。本轮没有把失败断言改成 true/false 的新预期，没有给测试添加 skip/todo，也没有把当前 61/62 宣称为 62/62。
