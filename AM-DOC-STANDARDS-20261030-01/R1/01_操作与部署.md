# 操作与接续

这是对现有 AM 的增量。不要用审核包整体覆盖运行工程，不要替换后来并行开发的模块。`source/` 中的文件应与本机最新工作树比较；`diffs/source.patch` 是本任务提交相对已注明基线的差异，`runtime-concurrent-context.patch` 标明保留的并行上下文。

## 配置与运行

私有配置位于原服务运行根目录的 `config/document-standards.json`，权限为 `0600`。参考文件为 `source/FS-AGENT-GROK-POC-20261017-01_R1_Studio/config/document-standards.example.json`，默认关闭且没有真实身份或数据入口。

目录、原件和保存通道绑定现有本人 CLI 身份；固定已有 profile、应用身份、用户身份及可执行文件指纹。配置不能从模型或消息正文构建。没有使用新增账户或应用权限。当前项目台账仍使用既有授权的读取方式，`ledger_write` 必须为 `false`。

保存目标是本人可访问的草稿位置。模板副本创建后，先关闭链接分享和外部访问，并读取设置核验，之后才填写项目数据；不改源模板的权限。修订输出新副本，原稿保留。

停用本功能：将该私有文件的 `enabled` 改为 `false`，在原任务空闲后重启原桥接服务。原文档、查询和模型服务保留；不要新起消费者或停止共享 Ollama。关闭功能后，新增本地正文仍按原期限清理。

## 使用

先用 `/doc 模板帮助` 查看说明。格式为：

```text
/doc 模板 文种 项目编号 项目类型 项目级别
```

文种为“章程”“变更申请”或“结项报告”；类型为 IPD、IRAD 或 other，级别为 L1／L2／L3。类型和级别是本次明确选择参数，不能代替批准记录。模块按准确项目编号定位，不用相似项目名猜测。

后续文字和附件继续属于本稿；明确标为范例／模板的文件、其他项目或混合项目资料需要先明确用途和范围。补充后会重新形成候选稿；缺失资料保留。

- `/doc 采用`：仅记录采用当前附件稿文字，不代表审批或挂载。
- `/doc 保存云文档`：保存本人可访问的模板副本并独立回读。
- `/doc 云端更新 章节名称`：仅处理指定章节，复核后保存新版本。也可通过稿件操作按钮选择章节。
- `/doc 云文档对账`：读取已有动作结果；不重发未知写入。
- 挂载继续使用原选择目标、预览、确认和对账流程。模板稿新增项目和文种一致性检查；当前旧“测试报告”目标未被扩大。

## 复现检查

原环境检查命令和结果在 `verification/VALIDATION.json`。公开包可运行：

```sh
python scripts/verify_export.py
```

该命令在临时目录组装纯验证依赖，执行本轮新增宿主检查和原包核心检查，不读取本机业务配置，不连接 Qwen／飞书，不安装服务。需要 Python 3.12 和 pytest；不会自动下载依赖。

`validation_support/` 仅为这些检查补齐未修改的原 AM 通用依赖，不应覆盖运行服务。`engine_reference/` 中全部是原包合成示例和检查。

真实验证脚本需要显式传入原服务配置、私有目录和准确项目。它们复用原模型协调器，没有消息消费者；真实资料只保存在私有输出目录。`--save-native` 会执行已授权的本人草稿保存，不能对未授权目标随意运行。脚本结果不能替代真人操作或专业验收。
