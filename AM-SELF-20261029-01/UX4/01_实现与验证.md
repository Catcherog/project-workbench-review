# UX4 实现与验证

依据完整 `UX4-v1.0-exec`，原工程基线 `7ecd04824bd60c97db83f6cd17ad1082fbb3044c`。开工已跟踪文件无后续改动，既有未跟踪资料保留。最终源码 `c4217463ceb99f2f7baf254a0aaa582dd33cb7ac`。

## 已实现

- 待发送结果提交成功后才唤醒原循环；结果工作线程、资料刷新和投递结束也通知现有循环。清除通知移到状态检查之前，避免漏唤醒；没有增加飞书消费者或使用毫秒轮询。
- 查询身份继续按稳定用户 ID、当前服务 app/tenant 隔离使用 600 秒结论。私聊与群只读共用；当前禁用名单和群披露范围仍本地检查。瞬时网络失败不提前丢弃原有效结论，也不续期；明确否决立即失效。管理与真实发送仍走原校验。
- 部门目录共享一次在途完整读取，根部门用户不需读子部门树；子部门身份截止受目录截止约束。启动后台预热目录与资料，延续原快照更新、版本与过期规则。
- 源资料完成前，未发出的加载卡可合并；已有可靠页面的刷新保留原读取时间，完成后只发布一次结果。首次无可用页面仍有加载与恢复路径。
- 已批准群的目录、明确编号、名称、已记录别名、字段与引用查询进入同一查询服务。明确问题由代码完成；语义不明才用原 Qwen。群 I/O 在原有 3 个有界查询工作线程内，不占主循环等待或把全部 HTTP 放入模型通道。
- 群答案是原消息/话题下的公开卡片，按问题提取字段。公开卡片保留，按钮不会替换它。普通同事不出现管理按钮。
- “私聊继续”创建点击者的个人视图，保留来源群范围；成功的飞书发送回执用于绑定实际私聊，无需再次远查同一聊天。群目录、搜索、计数、栏目和来源链接均应用范围过滤。另开正常私聊查询入口才使用已批准的全台账私聊范围。
- 引用 AM 公开答案时，使用消息与项目绑定，允许同群另一名已授权用户追问；无引用只承接同一用户/群/话题。多项目引用保留可点候选，不猜唯一项目。
- 热私聊导航可直接在回调中返回生产卡片，必须有有效身份、本地快照、操作者/消息/版本绑定。慢源、过期身份、管理动作仍异步。同版本不再另排 PATCH。回调返回与平台应用分别记录，未知状态不作为未发送；下次真实点击新 nonce 或独立回读才确认应用。
- 普通异步查询页面使用约 1/20 抽样完整回读；异常与未知恢复仍核对。业务流程的核验没有改为抽样。
- 本人个人项目视图沿用单页跟进表单与准确预览，并带入已核实的来源群。未创建真实提醒、订阅或正式台账写入。

## 群卡兼容结论

在原已授权测试群，仅给本人发出一张无业务内容的 2.0 ephemeral 卡片，返回成功；桌面观察到“仅对你可见”标识。但常规 PATCH 返回 `230001 / invalid message_id`，该路径独立回读未通过。不能将此组合当作已验证的连续个人群内浏览。

因此生产采用执行稿允许的“私聊继续”。没有把普通群卡设置 `update_multi=false` 后冒称独享，也没有扩大群范围。ephemeral 回调更新、话题群组合、另一设备和另一人不可见性仍未完成真实验证；当前生产不依赖它们。

依据：[最小真实兼容测试](evidence/ephemeral-compatibility.json)。[飞书官方消息 API 概述](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1)列有该发送能力；当前 PATCH 限制以本次实测为准。
