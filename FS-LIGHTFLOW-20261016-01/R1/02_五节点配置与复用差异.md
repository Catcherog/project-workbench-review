# 五节点配置与复用差异

最终保存版本：TEMPLATE-R1 v7。节点ID及前后依赖保持，系统开始后依次为项目启动、方案与计划、执行与推进、验证与验收、结项。五个业务节点均采用原生技术完成操作；无完成意见、整体完成结论或逐人批准必填；节点事件没有真实审批、消息或外发动作。

| 节点 | A中的独立记录 | 现有原生完成条件 |
|---|---|---|
| 项目启动 | 章程与立项依据1项 | 当前项目测试记录含模拟立项通过标记；已关联且节点标识匹配的成果全部已审核 |
| 方案与计划 | 方案及验证策划1项 | 匹配本节点标识的已关联成果全部已审核 |
| 执行与推进 | 工具包、使用资料、资料入口3项 | 同上；不要求PM或工作台二审 |
| 验证与验收 | 验证、移交2项 | 同上；验证通过语义未被检查，见失败项 |
| 结项 | 最终验收与结项依据1项 | 模拟最终验收结项标记；本节点已关联成果全部已审核；未重检前阶段必交项 |

状态计算规则：结项节点已完成时，当前测试项目显示已完成。该规则在v7保存；A/B经明确实例升级并读回v7，升级预览无新增、删除节点或解绑成果。核心缺项与审核用例在v6完成，v7只增加状态映射，另验证了A最终状态与B缺项拦截。

实际复用：项目描述、节点负责人、交付物负责人、交付物审核的未审核/已审核、成果版本、补充要求、专业结论与依据、适用性及原因、原生父子关系和资源入口。没有新增字段或改变原字段语义。

资源名称和标准说明不可在实例中改写。合成业务内容写入独立实例补充要求，资源母本保留。验证策划在方案主记录中；同一成果在结项通过确定版本及主记录链接引用，不新增副本。未登记计划日期、估分或实际工时。

当前校验的实际含义是：先从项目关联成果中按可编辑的“所属节点稳定ID”筛选，再检查已审核标记。真实节点关系另通过节点接口读回；该条件本身不证明节点关系与标识永远一致，亦不证明固定应交项齐套。空集合为真、待判断范围、负面验证结论及跨阶段必要移交均存在缺口。

最小后续修复方向（未实施）：在保持五节点和两次决定的前提下，以固定应交基线、真实节点关系及既定专业结果建立非空/齐套/适用性检查；结项重检必要验证及移交，成果变化使相关检查失效。计算字段容量限制应先解决或找到经实测的等价原生机制，不改旧公式、不建立PM内容二审、不新增项目评审。
