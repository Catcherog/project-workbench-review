# 候选集成差异

差异基于实际原机当前文件和校验后的 R2 原包，见 `source/r2-native.patch`。`source/local-qwen3.8/feishu-bridge/bridge.py` 包含原机既有 Grok CLI 变化；补丁只表示本轮在其上增加的内容。

| 文件 | 本轮内容 |
|---|---|
| `am_gateway_r2_host.py` | 关闭时直接返回；启用前拒绝旧 Grok 路由并存；验证模块实际路径，生成加载文件指纹 |
| `bridge.py` | 原连接内的接收/卡片/撤回/退出钩子，不新建消费者；保留原业务路径 |
| `integration/studio_host.py` | 身份和披露范围校验、原控制动作分流、SDK 收发/回读、Qwen 协调器接入、采集绑定、产物本地核验 |
| `integration/r2_runtime.py` | 可选采集工厂在网关建好后绑定同一 Store，避免另造一套状态 |
| `examples/studio_config.disabled.json` | 默认全关闭；真实 URL、CLI 命令和隔离证据仍为空 |
| `tests/r2/test_studio_host.py` | 28 项原机接线边界测试，覆盖自身回声、权限、原流程保留、去重与不确定结果 |
| `tools/probe_studio_reads.py` | 可重复的有界真实只读验证，不启动消费者或发送消息 |

## 已验证的关键行为

- 历史响应中原应用 ID 映射为已绑定 bot open_id，避免机器人回复被私聊路由再次处理。来源租户、会话和 thread 范围在 transport 校验。
- 入站回调只做本地检查；调用模型/发送前使用原身份缓存或原群成员检查；未扩大部门、群披露或其他人私域权限。
- 原 `/doc` 等命令、训练控制、原文档会话、编辑采集、已存在的原消息/群回复、原卡片及待确认选择继续由原流程处理，不使用旧自然聊天 catch-all 作为新路由判定。
- Qwen 经过已有 ModelCoordinator，不直接绕过资源锁访问 Ollama；run_id 按现有 provider 要求使用 32 位十六进制。
- 发送 UUID 按动作生成，受理和正式结果独立；先持久化发送意图，未知结果不自动再发。已取得平台 ID 的结果能按作者、会话、话题、父消息、类型和正文独立回读。
- 未取得平台 ID 时保留 unknown；当前未实现从飞书按 UUID 查询不存在的接口，不能靠同文内容匹配推断发送成功。

## 未完成及限制

- Grok Bot：没有真实结果 API/完成回传与严格无记忆证据，不能启用。
- Grok CLI/Codex CLI：仅保留管理员配置的 JSON argv 接线位置；未实现/验收原生命令 JSON wrapper 与完整隔离，不算已连接。没有改变默认模型或用其他执行端替代。
- 附件：已实现允许目录、普通文件、大小和 SHA-256 的本地产物校验；多文件上传/消息回执未绑定。发送端在有 artifacts 时明确失败，不能只发“文件已生成”冒充交付。
- 采集：绑定当前披露群和本人 AM 私聊；群目录发现只登记现有批准子集。本人对同事私聊、其他资源域和全历史未接入。
- 原项目/事项投影：未绑定 `ExistingStateProjection`，未创建第二套同名待办或写外部台账。
- 新增测试依赖原机已有 AM 模块及安装的 SDK。公开副本提供本轮变化和关键源码，不包含原机全部宿主、私有配置和数据库；不能当成独立部署包。

`native_memory_verified` / `isolation_verified` 是启动前检查结果的声明，不是实现记忆关闭的开关。当前用户核实与官方说明不足以设置为 true；保持未验证。
