# R3 接续运行与回退

此目录是隔离候选，不是生产安装包。既有 R2 兼容代码保留，`implementation=phase1` 的真实激活分支明确拒绝缺失的 Grok Bot 接口。`install(ports, activate=False)` 供本地验证，既不新建飞书连接，也不自动启动调度线程。

## 可复现验证

使用 Python 3.11 以上和 pytest，在 `am-grok-realtime` 目录执行：

```sh
python -m pytest tests/phase1 -q
python -m pytest -q
```

第一条只需 pytest；完整回归还需要原机既有 AM 模块和 lark_oapi SDK。真实宿主的源代码与 SDK 需由现有运行环境提供，不从审核包猜装生产凭据。审核包保留新增源码、改动 diff 和必要基线引用，不包含全部原机环境。

`tools/run_phase1_local_check.py` 在临时数据库中演示默认 Grok Bot 待接入、持久任务、本人补充立即可见及来源撤回；它不会发送飞书或调用模型。输出明确标注合成环境，不能作为实际 Bot 回执。

## 数据和恢复

候选在既有 Store 中使用增量 `h1_` 表，保留 `gw_items` 来源及版本。不要对同一个数据库同时运行 R2 Router 和 Phase1 Harness。只有一个运行模式负责该范围的任务受理；切换模式前要核对来源游标、认领及发送账本。

1. 来源获取失败：保留游标和原资料，`h1_sync` 标记失败及覆盖缺口；下一次从保存位置补漏。
2. 路由中断：待消费责任保留；纯分类租约过期可重做，但业务操作不重做。
3. 接单或结果未知：保留原任务、操作身份和执行范围，等待实际接收端查询或可信回执。
4. 已发送但回执丢失：先获得稳定效果编号到输出消息的精确映射，再独立回读；不以同文、同线程或近似时间认定成功。
5. 权限或资料变化：收紧任务策略，使快照失效；已有外发是否发生仍需独立核对，不承诺撤权可以撤回已交给平台的请求。
6. 停用新链路：`prepare_rollback(scope)` 暂停派发并产出三类清单。旧入口导入排除项、明确积压承接方、确认旧执行器不再冲突后才允许交接。

R3 没有修改现网文件、重启服务、启用第二消费者、切换模型、训练、修改正式业务对象或真实外发。删除候选工作树不会撤销其他真实业务效果，数据库也不得回滚到旧快照。

## 下一次接续所需事实

- Grok Bot 真实领取任务和持久接单入口，以及稳定身份去重的可核对记录。
- 真实结果回传或状态查询方式，执行开始／结束及输出消息编号的关联证据。
- 实际读取、业务写入、发送、记忆与缓存的权限边界；群聊敏感资料场景需证明跨会话隔离。
- 原五分钟轮询的实际范围隔离或共同认领，以及回退历史状态导入能力。

这些缺口不能用本地文件、示例 URL、自定义接口、测试适配器或“已验证”配置项代替。用户已确认在缺口期间完成独立工程工作，因此本轮无需为这些已明确暂留的事项再次索要同一选择。
