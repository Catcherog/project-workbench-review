# R3 复审意见落实

本表是执行端自查，不代表 Gemini、Astra 或独立工程师已经复审本轮代码。源代码位于 `src/am_gateway/phase1/`；测试位于 `tests/phase1/`。

| 复审意见 | 实现和验证 | 剩余边界 |
| --- | --- | --- |
| Astra 1 事件保存后任务创建前退出 | `runtime.ingest/route_one` 同事务游标和待消费状态；子进程提交后 `os._exit(27)`，重启只形成一个任务 | 真实外部来源重投和跨主机失联仍待接入验收 |
| Astra 2 指纹字段边界 | `contracts.business_fingerprint`、`validate_envelope`；业务语义与传输、上下文、当前权限分离；测试路由升级及同键改载荷 | 接收端持久去重尚待 Grok Bot 实际实现 |
| Astra 3 旧轮询回退状态交接 | `cutover` 保存完成／未派发／未决三类清单，缺少排除项、承接方或旧实例停止证据即拒绝 | 未对真实 Grok Bot Routine 执行停用或导入 |
| Astra 4 受限试点与完整验收 | 默认全部外部能力待接入；`Phase1Ports` 与激活拒绝；启用范围和 41 项矩阵单列工程、真实、用户层 | 不能把关键权限项标为不适用或完整通过 |
| Astra 5 队列积压和截止时间 | 每执行范围 32 条默认上限，持久接单截止 120 秒、执行观察截止 180 秒；过期不唤醒，超时保留核对，不占用其他已隔离范围 | 数值为候选配置，负载和用户交互时限未校准 |
| Astra 6 重复乱序结果 | `lifecycle.record_receipt` 用事件键去重，终态不回退，矛盾结果记录冲突；旧代次不释放新代次 | Grok Bot 真实回执来源未绑定 |
| Astra 7 有效回复与完整任务分开 | `metrics` 保留六类结果、所有任务分母、首回复和完整交付时间、缺测及负值；小样本无 P95 | 没有完整真实端到端样本，不报告提速比例 |
| Astra 8 ACK 边界和分层验证 | 必须有稳定业务身份、run_id 和持久记录；HTTP 状态码不能满足 ACK；矩阵逐项注明主要方法 | 可信适配器可以承担持久接单，但当前 Bot 尚无该边界 |
| Gemini 工具包装层 | `boundary` 校验任务、代次、当前权限、资料版本、目标；发送效果唯一记录，未知结果不自动补发 | 这是本地候选端口，不能约束尚未接入的 Bot 直接 CLI、凭据与记忆 |
| Gemini 超时核对和终止闭环 | 记录 run_id/epoch，保留不明锁；取消和状态查询不支持时明确返回；确认停止且未决发送已核对才释放 | 本轮没有 Bot 进程句柄，未实现或声称可远程 kill，也未配置 2–3 秒自动接替 |
| Gemini 视图增量体积上限 | 增量条数和 UTF-8 字节上限、最低可见版本、视图滞后提示、按权限补查 | 外部 Bot 读取端尚未绑定，跨环境路径不能假定可达 |

## 自查发现并修复

- 序列化策略中的 tuple/list 差异导致首次文件交接测试失败，已将信封规范化为 JSON 原生类型。
- 提交来源编辑后、路由线程尚未处理时，认领仍可能使用旧请求；现在认领与工具调用都核对来源版本。
- 仅附件／原生修订变化时可能覆盖旧版本；现在保留原版本并建立新的本地修订。
- 执行器仍在发送或发送结果不明时，结束回执不能释放冲突范围；已补充独立发送映射及回读后恢复的测试。
- 使用系统 Python 跑旧测试时版本不满足包要求；使用上一轮隔离 Python 后又发现未带 SDK。最终复用 Python 3.12 和现有 SDK 路径通过，未向生产环境安装测试依赖。中间环境失败单独保留。
- Terra 的 CLI diagnostic error item 最初被误判为执行工具。修正为保留诊断计数并拒绝真实工具事件，独立合成调用通过 Schema；首次超时和中间诊断记录均保留。

- 派发认领现在只选已核实切换范围；已收录补充的原文编辑会更新信息版本，而不会产生第二个业务操作。
