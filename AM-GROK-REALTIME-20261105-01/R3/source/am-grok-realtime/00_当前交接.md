## 1. 本轮需求与既有约束

牧翊要求依照“对话入口与后台重业务分离”的架构完成设计和代码开发，并明确由 Codex 执行真实验收。

- Grok Bot 只处理机器人私聊、真实群 @、明确回复到已发机器人消息的续问。代码直接路由，无 Qwen 前置分类。
- Grok CLI 接管后台项目/个人事项整理和业务分析；Qwen 做轻量候选；Codex CLI 接文档/代码任务。
- 一条输入可以同时产生即时对话和静默事实更新，后台整理不阻塞回答、不额外群发。
- 普通事实直回；新业务决定、相关依据冲突等转本人预览确认；复杂任务移交后台并聚合一次正式结果。
- 群、话题、用户上下文隔离；私聊来源及其衍生字段不进入公开群；未发送草稿不进入正式对话记忆。
- 保留原身份、既有业务动作、现有模型选择及 `ledger_write=false`；沿用唯一飞书长连接。不能新开另一消费者覆盖实际服务。
- 当前仅交付候选代码与本地证据。本轮没有生产安装、真实模型调用、真实飞书发送，也没有向外部 Codex 自动派发任务。

## 3. 已实现的行为

1. 入站回调只进行本地规范化、入库、控制分流和唤醒；模型与网络读取在独立工作池。持久化后再路由，进程中断不依赖内存队列找回输入。
2. `gw_items` 保存原始规范化输入和版本；事件/轮询共同去重。富文本与附件引用共用规范化函数，重复采集不制造虚假编辑。
3. `gw_jobs` 区分任务、尝试、输出模式和回复归属。对话池与后台池分开；后台可按 2 秒、20 条、8,000 字符凑批。
4. 审核卡片绑定真实操作者、动作和草稿版本。修改输入、替换稿和编辑会话消费在同一事务提交；重复投递不会改第二次。确认直接发冻结文本。
5. 每个 `action_id` 独立生成发送 UUID，解决旧 `reply(mid,text)` 让受理/挂起提示与正式结果碰撞的问题。网络结果不确定进入 `unknown`，回查原发送，不盲目重投。
6. 快照按字段保留来源。群可见值和冲突候选分别检查来源权限；资源需 `shared_resource_chats` 显式共享。事实写入仅由 Grok CLI 执行；Qwen 只形成候选，Bot 无事实写权限。
7. 复杂请求的独立子任务统一聚合；子任务未知时保持等待。文件必须由宿主核验登记，实际发送另取平台证据。
8. `CollectionService` 统一后台发现与采集。live/history 各自持久化分页窗和水位；游标过期重读原窗，页内容与页进度同事务提交。采集状态与来源覆盖可只读导出。
9. 各 worker 期限分别配置；领取租约覆盖实际 worker 期限。异步 provider 的 run ID、接受/开始进度可落库，晚到结果保持同一任务/尝试关联。
10. `live_cutover_at` 首次持久化，重启必须复用。不能每次启动设为“现在”而漏答排队消息或重新补答历史问题。

## 4. 本地验证与真实验收边界

最终数量、环境、命令、退出码及被测源码指纹以 `verification/results.json` 为准。`verification/pytest-output.txt` 和 JUnit 文件保留原始测试输出。

本次最终完整回归为 **252 passed，0 failures，0 errors，0 skipped**，其中 R1 兼容测试 169 项、R2 测试 83 项，pytest 报告耗时 9.29 秒。验证环境为 Python 3.12.14 / pytest 9.2.0；43 个运行、接入与工具 Python 文件完成编译检查。

`tools/run_r2_demo.py` 实际启动本地 HTTP 服务和 Python 子进程，使用 SQLite 与真实临时产物，验证：

- 同一消息双派、重复采集不多答、后台更新静默；
- 敏感群问答 → 本人预览 → 修改完整草稿 → 新预览 → 确认原群发送；
- 多个后台子任务 → 一条受理提示 → 一条聚合正式结果，产物经本地核验。

模型输出和飞书发送使用替身。演示中的毫秒数不能作为 Grok 性能或手机响应证据；真实 API 回执也不能替代手机可见时间。
