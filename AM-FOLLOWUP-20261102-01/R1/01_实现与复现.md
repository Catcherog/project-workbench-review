# 实现与复现

`am_followup_host.py` 是原服务内的适配层；`am_followup_sources.py` 只读取原 FactEngine 与来源存储。`action_aliases`、`action_semantics`、语义历史及证据引用附属于原事项，不复制原始聊天成另一套权威库。

参考准入模块保留精确批准、注意对象唯一键、跨轮未决屏障和稳定 UUID。新 `followup_adoptions` 与原 plan、occurrence、approval 在同一原 SQLite 事务生成；崩溃后继续采用已有 intent，不能换键重建。原 Scheduler 的实际循环同步调用 `dispatch_once`，不会返回 queued 后另由裸发送 worker 处理。一次性 hook 在所有实时核验之后、同一原 SQLite 最终写事务中再次核对原事项、语义版本、计划、批准及暂停，防止慢目录调用期间的暂停被遗漏。

BusinessPort 新增独立 recipient_p2p。其目录身份必须经过原在职/TH2 核对；机器人单聊由原保留期内真实入站消息精确回读证明。姓名缺失仅可关联原获准群的确切成员 ID。该设计当前会拒绝没有有效单聊证据的工程师，不通过读取过期内容解除。

披露快照单独绑定全文、精确受众、字段引用、策略版；群消息核对全群成员。私聊必须有单独的字段/用途策略，或已获准的源群披露范围内同一成员等明确依据。源中明确禁止或私人信息继续拒绝；R1 没有附件发送能力。来源重新核验失败、必要缺口或未知发送只影响关联动作。

原生回调从原 SDK 和入站队列进入；真实预览必须在原 outbox 标为 sent，并精确回读消息、会话、机器人及卡片渲染指纹。确认后正文冻结。view/modify/stop 不批准发送；修改使旧预览失效。新一轮只能来自明确的 owner 新请求，不能通过换文案、渠道或生产者绕过 unknown。

原反馈及关闭权限保留。新的自然 reply 只接受对已绑定实际消息的回应；非唯一关联和完成自报不关闭业务。四维语义需要原事实引用与受信审核；不是通用自由文本语义验证器。

## 审核重建

审核源码是相对固定 R3 的增量。先使用固定 R2-FIX2 source，再叠加固定 R3 source，最后本轮 source；`scripts/reconstruct.py` 校验前两轮审核文件清单后完成此步骤。不得把这些脱敏副本装回原服务。

```sh
python scripts/reconstruct.py --r2 ../R2-FIX2 --r3 ../R3 --overlay . --output /tmp/am-followup-review
python scripts/run_checks.py --source /tmp/am-followup-review/source --output /tmp/am-followup-checks
```

需原 Python 3.12、项目依赖与 pytest。最终应保留原 27 项失败；这是实际退出码 1，不能改称全绿。新增用例位于 source 中的 `tests/test_followup_native.py`。`reference/` 保留设计参考实现及原 157 项合成检查，生产未调用其独立 EvidenceLedger/IdentityRegistry。

本机维护脚本只操作原服务，持有原模型租约、检查业务空闲并私下备份。沿用上轮已证明过期只读验证标记的维护例外，原未知业务不清理、不重放；Qwen/Ollama 不停止。安装和运行记录应与最终源码 SHA 联看。
