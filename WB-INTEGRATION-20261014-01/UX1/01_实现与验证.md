## 关键实现

原事项输入与全局助手将输入放在结果之前，保留最新一轮可见，旧轮次按需展开。此前回执收起，但查看、修改、撤销与时间入口保留，仍由持久作用域保护。原事项提交按钮使用同时覆盖记录与讨论的名称；生成待审草稿及核实原提交单独命名。

协作批次上方显示当前批准条数和纳入事项数，保存操作在批次内保持可见。完整正文未截断，执行范围仍是独立展开区，提供定位入口；上方选择不变成发送过滤条件。工作区和原请求保护、失效选择退出、有效选择保留等原逻辑保持。

变化栏先比较实际字段，有差异才出现。草稿阻塞以具体消息列出，并可切回全部记录定位；只读草稿展开后仍须明确放弃，放弃只清理本地缓存。原请求未知结果没有因文案简化而丢失查询或续办入口。

CoreMaterials 使用当前工作区真实资料 ID 获取已有来源，复用 EvidenceReader 显示留存正文和原件，不进行云端权限变更。阅读对话框独立处理 Esc、Tab 和取消事件，阻止嵌套取消传播至原事项；返回恢复焦点，原输入组件不卸载。不存在的资料明确提示，读取错误和来源失效保留原状态。

## 验证中发现并处理的问题

资料阅读的第一次 Esc 会把取消事件传到外层事项并关闭原事项。已在内层阅读器隔离按键、取消及关闭事件，实际浏览器和应用内复核均通过。

旧回归脚本对“发送”按钮、总记录数文案和默认展开历史的假设随 UX1 调整；只修改对应定位和展开步骤，原业务断言保留。未把这些预期变化当作业务逻辑失败，也未通过删除断言掩盖问题。

一次 DEV1-FIX1 回归误用了不生效的输出变量。该次四个生成文件已转存 UX1，旧目录对应四份文件从原固定公开包逐字恢复；原 GitHub 固定提交没有变。本轮最终证据来自指定的新目录，不覆盖旧轮次证据。

原型与完整业务验收不同；本轮通过仅支持上述体验改动和受影响边界。P1 历史结项保留，P2 至 P5 的真实链与本人验收仍待完成。
