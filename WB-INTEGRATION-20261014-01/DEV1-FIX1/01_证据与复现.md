## B01/B02 的判定依据

B01-A 的页面勾选绑定旧指纹；外部原 HTTP 编辑后，回读使新版本显示未选中，重新勾选才产生一次批准 POST，提交的 fingerprint 等于新指纹。B01-B 通过原 `/api/v2/work-items` 更新候选优先级产生真实新版本，重新纳入时 admissions 使用该版本，decisions 为空。B01-C 已由外部批准的消息历史保持原条数，当前页面只提交同批另一条。B01-D 同时有有效和失效选择，实际只清除失效项。

B02-A/B 通过原 HTTP 取消或执行原批准稿，页面回读到 cancelled/readback_verified 后仍可查看未提交草稿。放弃前后比较完整服务器状态，并记录页面 POST 与模拟发送计数：均无变化；同批另一条有效已批准消息恢复可执行。测试没有点击恢复后的执行按钮，所以“放弃”不能夹带发送。

B02-C 在同一个 tab 中刷新并切换入口后重新进入，草稿按既有 sessionStorage 边界保留；明确放弃后刷新不复活。没有将此结论扩大为跨 tab、跨浏览器或重启后的持久草稿保证。

GUARD-inflight 使用可暂停的合成传输，原服务实际记录 sending/sent；回读前批次执行仍禁用。相邻 19 组继续验证 unknown 先查、人工接手、筛选、可编辑草稿、旧指纹与恢复副本等限制。新增过滤只删除选择，不生成批准/纳入/发送请求。

## 复现

在独占工作树、已有依赖和浏览器条件下应用 [product.patch](changes/product.patch)，使用原工程：

```sh
npm run typecheck
npm run build
node scripts/test-integration-plan1.mjs
node scripts/test-integration-dev1-fix1-browser.mjs
PM_DEV1_OUTPUT=output/dev1-fix1/dev1-regression node scripts/test-integration-dev1-browser.mjs
```

新增脚本默认记录修复后的验收。仅在原 DEV1 产品基线上设置 `PM_EXPECT_BASELINE_BUGS=1` 运行同一脚本，才会检查五个已知缺陷是否复现；这不是绕过验收的模式。浏览器与 Playwright 都定位已有安装，可用 `PM_CHROME_PATH`、`PM_PLAYWRIGHT_MODULE` 指定现有路径。

本包也保留 GPT 局部脚本 [reproduce-dev1-review.cjs](tests/reproduce-dev1-review.cjs)。从产品根目录使用 `NODE_PATH="$PWD/node_modules" DEV1_SOURCE_ROOT="$PWD" DEV1_REVIEW_OUTPUT=<已有输出目录>`，运行该脚本并带 `--expect-fixed`；它不启动真实 React/HTTP，不代替浏览器。

所有服务使用独立数据目录、动态回环端口、testMode:true、legacy:null。未读取或写入正式业务库。公开日志只替换用户主目录/工作树路径并去除末尾多余空行，源码副本与受测字节一致；凭据、私人聊天和数据库没有上传。
