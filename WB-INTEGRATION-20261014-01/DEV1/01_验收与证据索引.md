## 应先检查的必要差异

1. Q01 已由用户明确接受。面板默认启用两步交互；批准按钮只保存决定，执行按钮在展开的整批范围中。未保存编辑、筛选、指纹不符、未知/待回读状态和人工接手继续限制执行。
2. 原请求层保留 HTTP 状态码，避免 409 明确拒绝被当作未知；跨事项批次补读相关事项的实际版本；后段未完成时留在原输入面板，展示持久回执和失败原因。
3. 原发送服务对没有交付物目标的普通协作消息增加一个可选访问保护，修复实际执行时的 500。所有其余业务检查沿用原服务。
4. 相邻 F02 测试从“整个工作区版本不变”改为“业务 P1 状态不变”，因为 P2 会先持久保存原始输入。修改后的 F02 和 DEV1 的输入竞争用例均实际通过。

## 复现与停止点

在精确产品基线的独占工作树应用产品补丁，复用已有依赖后：

```sh
npm run typecheck
npm run build
node scripts/test-integration-plan1.mjs
node scripts/test-core-input.mjs
node scripts/test-core-chain.mjs
node scripts/test-s1p1-fix1-domain.mjs
node scripts/test-integration-dev1-browser.mjs
```

浏览器脚本仅定位现有 Playwright 和 Chrome，可通过 `PM_PLAYWRIGHT_MODULE`、`PM_CHROME_PATH` 指向已有安装；不安装依赖。相邻回归使用 `PM_FIX1_CASES=F01-UI,F03-UI,F04-UI,F06-UI` 及 `PM_FIX1_CASES=F02-UI,F02-reload,B15-position` 两次运行 `scripts/test-s1p1-fix1-browser.mjs`，以 `PM_S1P1_OUTPUT` 指定本工作树输出。

公开日志只将用户主目录及工作树路径替换为 `/REVIEW_HOME` 和 `/REVIEW_WORKTREE`；不包含令牌、私人聊天、真实业务记录或 SQLite 数据库。原始证据留在执行端。输入 SHA、实际消息截止和 Q01 覆盖关系见 [input readback](evidence/input-readback.json)。

复杂真实模型后段、同事真实链、持续接收/长期运行、用户验收分别未完成，安排及权限停止点见当前交接。原 P1、R2-FIX1/A1、UI R2 结论继承；本轮没有重复 A1，也没有安装、生产迁移、调度启用或产品源码 push/merge。
